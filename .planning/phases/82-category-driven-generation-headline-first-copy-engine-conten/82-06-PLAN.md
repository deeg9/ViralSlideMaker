<objective>
Fix Gap A from the R10 visual sign-off: `clampManualHookSize()` flattens every manual hook size to `MANUAL_GROWTH_MAX = 1.6x` the auto-fit value, so a user entering 190 vs 290 in the editor gets identical rendered output and the news headline can never be made large enough to dominate the slide like the reference (`~/Desktop/Screenshot 2026-05-17 at 2.13.25 PM.png`).

Root cause (verified): `src/lib/render/hook-fit.ts:171-183` — `MANUAL_GROWTH_MAX` is a fixed 1.6x multiplier of the auto-fit size. The original rationale (`quick-260510-export-overlap`) was: a too-big hook on a NEWS_LAYOUT cover/body slide wraps into more lines than the fixed `(bodyY - hookY)` zone can hold, causing hook+body overlap on export. **That rationale only applies when the slide HAS a body.** Phase 82 News slides are headline-only (R4 — `body_text` is optional, headline-only is the default), so there is no body zone for the headline to collide with — the cap is doing pure harm there.

Fix: make the cap body-aware. When the slide has NO body text box, `clampManualHookSize` must NOT clamp at all (return `manualSize` unchanged) — the headline owns the whole canvas. When the slide DOES have a body, keep an overlap-protecting cap, but raise `MANUAL_GROWTH_MAX` substantially (1.6x -> 2.6x) so a legitimately large user pick survives. Also raise the editor hook input `max` from 240 to 400 so the UI can express the larger sizes the renderer now honors.

Output: `clampManualHookSize` takes a `hasBody` signal; both renderers thread it; `ActiveTextBoxCard` hook `max` raised to 400; `hook-fit.test.ts` pins the new behavior.

NOTE: This change legitimately alters render output for news-layout templates (`news-cyan`, `news-drop`, `tr3nding-news`, `magazine-bold`) ONLY when a slide carries a manual `hook_font_size` above the old cap. Render-parity snapshot regen is scoped + intentional — see Task 4.
</objective>
