From `src/lib/editor/editor-actions.ts`:
```typescript
| { type: 'SET_LOCKED'; slideIndex: number; ids: string[]; locked: boolean }
| { type: 'SET_HIDDEN'; slideIndex: number; ids: string[]; hidden: boolean }
| { type: 'Z_ORDER'; slideIndex: number; ids: string[]; op: 'forward' | 'backward' | 'front' | 'back' }
```

Reducer behavior (from Plan 64-01..03 SUMMARYs):
- SET_LOCKED: single pushHistory; reducer trusts caller-supplied `locked` boolean (caller computes toggle math).
- SET_HIDDEN: same as SET_LOCKED with `hidden` field.
- Z_ORDER: single pushHistory; per-scope routing internally (text_boxes ∪ custom_images); watermark single-slot is implicitly handled via no-scope-changed short-circuit (a single-element scope's forward/backward op is structurally a no-op).
- All three actions ref-equal-short-circuit on no-op, so adversarial inputs (clicking lock on already-locked element, clicking up-arrow on top element) don't pollute undo history.
