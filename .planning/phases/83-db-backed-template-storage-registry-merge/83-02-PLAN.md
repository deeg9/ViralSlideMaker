<objective>
Add the hybrid sync+async registry layer on top of the existing code-template registry. A new `registry.ts` module merges the 13 synchronous code templates with DB template rows from the Phase 83 `templates` table — exposing `resolveTemplate(id)`, `getPickerTemplates()`, and `isKnownTemplateId(id)` — behind a ~60s in-memory TTL cache, with a fetcher test seam so the merge is hermetically unit-testable with no live DB.

Purpose: TSTORE-02 — `getTemplate` / `pickerTemplates` / `TEMPLATE_IDS` must resolve both code templates and DB rows from one merged registry, so a DB template appears in the picker with no code deploy. The 13 code templates STAY in the synchronous `templates[]` array (CONTEXT.md "Registry Merge Architecture"); the merge happens only in this new accessor layer, so `legacy-templates-byte-identical` and `new-templates-parity` stay green with no fixture regen — `index.ts` is not edited.

Output: `db-template-row.ts` (the `DbTemplateRow` type + `dbRowToSlideTemplate` mapper), `registry.ts` (the async hybrid registry with TTL cache, collision rule, picker ordering, and fetcher seam), and a hermetic unit-test suite.
</objective>

    1. Header comment citing Phase 83 (TSTORE-02): hybrid sync+async registry — 13 code templates stay sync in templates[]; this layer adds DB-aware resolution behind a ~60s TTL cache.

    2. Define a `DbTemplateFetcher` type: `() => Promise<DbTemplateRow[]>`. Implement the default fetcher `defaultDbTemplateFetcher` that:
       - calls `await createClient()` (from `@/lib/supabase/server`),
       - `await supabase.from('templates').select('*').order('created_at', { ascending: false })`,
       - returns `data ?? []` on success; on any error returns `[]` (the registry must NEVER throw — a DB read failure degrades gracefully to code-templates-only).

    3. Add a TEST SEAM: a module-level `let activeFetcher: DbTemplateFetcher = defaultDbTemplateFetcher` plus two exported functions — `__setDbTemplateFetcher(fetcher: DbTemplateFetcher)` to inject a fixture fetcher, and `__resetDbTemplateRegistry()` to restore the default fetcher AND clear the cache. Name both with the `__` prefix so it is obvious they are test-only seams.

    4. Add a short-TTL in-memory cache over the DB rows:
       - `const DB_TEMPLATE_TTL_MS = 60_000` (~60s, per CONTEXT.md).
       - Module-level `cache: { rows: DbTemplateRow[]; fetchedAt: number } | null`.
       - `async function getDbRows(): Promise<DbTemplateRow[]>` — if `cache` exists and `Date.now() - cache.fetchedAt < DB_TEMPLATE_TTL_MS`, return `cache.rows`; otherwise call `activeFetcher()`, store `{ rows, fetchedAt: Date.now() }`, return `rows`. Wrap the fetch in try/catch — on error return the last cached rows if present, else `[]`.

    5. Export `async function resolveTemplate(id: string): Promise<SlideTemplate>`:
       - First check the SYNC code registry: `getTemplate` falls back to `templates[0]`, so instead use `templates.find((t) => t.id === id)` — if a CODE template with that id exists, return it (code wins over DB — collision rule).
       - Else `await getDbRows()`, find a row with `row.id === id`; if found return `dbRowToSlideTemplate(row)`.
       - Else fall back to `templates[0]` (mirrors the sync `getTemplate` fallback contract so callers never get undefined).

    6. Export `async function getPickerTemplates(): Promise<SlideTemplate[]>`:
       - `await getDbRows()`, map each row through `dbRowToSlideTemplate`.
       - Drop any DB row whose `id` collides with a CODE template id (code wins — do not show a duplicate).
       - Return `[...dbTemplates, ...pickerTemplates]` — DB templates FIRST, then the code `pickerTemplates` (CONTEXT.md "Picker ordering: DB templates appear first").

    7. Export `async function isKnownTemplateId(id: string): Promise<boolean>`:
       - true if `id` is in the sync `TEMPLATE_IDS` OR matches a DB row id from `await getDbRows()`.
       - This is the async DB-aware companion to the static `TEMPLATE_IDS` allowlist (CONTEXT.md: `TEMPLATE_IDS` stays code-only as the static validation allowlist; `isKnownTemplateId` is the separate async check).

    8. The module must NEVER throw from `resolveTemplate` / `getPickerTemplates` / `isKnownTemplateId` — all DB I/O is wrapped so a DB outage degrades to code-templates-only behavior.

    Do NOT edit `src/lib/render/templates/index.ts`. Do NOT change any render-path function signature — render functions already take `SlideTemplate` objects.
  </action>
