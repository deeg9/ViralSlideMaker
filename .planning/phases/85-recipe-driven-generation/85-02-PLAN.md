  <action>
Create a NEW module exporting:
  `export async function resolveLayoutRecipe(supabase: SupabaseClient, templateId: string): Promise<LayoutRecipe | null>`

Behavior (per 85-CONTEXT.md "Recipe-present detection"):
  - The 13 CODE templates carry NO layout_recipe — only DB templates can. If `templateId` is a code-template id (check against `TEMPLATE_IDS` from `@/lib/render/templates/index`), return `null` immediately WITHOUT a DB round-trip.
  - Otherwise query the `templates` table for this id's `layout_recipe` column:
      `supabase.from('templates').select('layout_recipe').eq('id', templateId).maybeSingle()`
  - If the row is missing, `layout_recipe` is null, or the query errors -> return `null` (NEVER throw — mirror the registry.ts "never throws, degrades gracefully" contract; wrap in try/catch).
  - If `layout_recipe` is a non-null object, run `parseLayoutRecipeSafe(layout_recipe)`. If `result.ok === true` -> return `result.recipe`. If `result.ok === false` -> return `null` (a malformed recipe degrades to the no-recipe path — generation must never break on bad recipe data).

Import `LayoutRecipe` type from `@/lib/types/layout-recipe`, `parseLayoutRecipeSafe` from `@/lib/validators/layout-recipe`, `TEMPLATE_IDS` from `@/lib/render/templates/index`, `SupabaseClient` type from `@supabase/supabase-js`.

Add a clear docstring: this helper is the single recipe-resolution entry point for the generation pipeline; it never throws; a null result means "no recipe — applyLayoutRecipe is a no-op".
