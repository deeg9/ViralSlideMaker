  <action>
Create a NEW module — do NOT extend style-spec-projector.ts (that file is the StyleSpec/reference path; the recipe path stays separable per 85-CONTEXT.md).

Export a pure function:
  `export function applyLayoutRecipe(slides: Slide[], recipe: LayoutRecipe | null | undefined): Slide[]`

Contract (mirror the style-spec-projector purity contract — pure, immutable, no I/O, no Date.now, no random, no console, no Gemini, no Supabase, no React imports):
  - If `recipe` is null/undefined → return `slides` UNCHANGED (return the same reference is fine; or a shallow map producing byte-identical objects). This is the SC3 no-op early-return.
  - Otherwise return a NEW array of NEW slide objects (never mutate input slides). Each slide gets a merged `style_overrides` — spread existing `style_overrides` FIRST, then recipe-derived fields, so the recipe overrides template defaults but the merge preserves any field the recipe does not touch.

Role -> slide mapping (SAME logic as Phase 84 extraction, per 85-CONTEXT.md — do NOT use assignSlideRoles from role-distribution.ts, that is the unrelated 5-value cover/reframe/support/pivot/close enum):
  - index 0 -> RecipeRole 'cover'
  - any slide with `is_cta === true` -> RecipeRole 'cta'
  - all other slides -> RecipeRole 'body'
  Implement a private helper `recipeRoleForSlide(slide: Slide, index: number): RecipeRole`.
  A recipe role may be ABSENT (`recipe.roles.body` undefined etc.) — when the resolved role is absent, that slide gets NO recipe-derived overrides (skip-emit; the slide passes through with its existing style_overrides only).

Caption-card geometry mapping (recipe `RoleLayout.caption_card: CaptionCardGeometry` -> existing `caption_bar_*` style_overrides, 1:1):
  - `caption_card.enabled`    -> `caption_bar_enabled`
  - `caption_card.x`          -> `caption_bar_x`
  - `caption_card.y`          -> `caption_bar_y`
  - `caption_card.width`      -> `caption_bar_width`
  - `caption_card.height_pct` -> `caption_bar_height_pct`
  - `caption_card.blend_pct`  -> `caption_bar_blend_pct`
  - `caption_card.opacity`    -> `caption_bar_opacity`
  - `caption_card.position`   -> `caption_bar_position`
  When `caption_card` is absent on the role, emit NONE of the `caption_bar_*` fields (skip-emit).

Hook placement: recipe `HookPlacement` has CLOSED-ENUM bands; resolve to numeric `style_overrides`:
  - `hook.position_band` (HookPositionBand: 'top'|'upper'|'center'|'lower'|'bottom') -> numeric vertical % via a deterministic band->numeric resolver. Define a private `const HOOK_POSITION_BAND_Y: Record<HookPositionBand, number>` table with representative values: top=8, upper=28, center=46, lower=66, bottom=84. Write the resolved y into `hook_position` (a TextPosition `{ x, y }` — preserve any existing `hook_position.x`, default x to 50 / center if absent). Reuse `computeCaptionBarBottomPositions` ONLY where the recipe role's caption_card.position is 'bottom' AND a representative bottom-band hook y is wanted — if reuse is awkward, the static band table is the authoritative resolver; document the choice in a comment.
  - `hook.font_size_band` (HookFontSizeBand: 'sm'|'md'|'lg'|'xl') -> numeric `hook_font_size` via a deterministic `const HOOK_FONT_SIZE_BAND_PX: Record<HookFontSizeBand,number>` table: sm=88, md=112, lg=140, xl=176 (px values consistent with the existing news headline ~124px default range).
  - `hook.text_align` ('left'|'center'|'right') -> `text_align` style_override (parity with SlideStyleOverrides.text_align).
  When `hook` is absent on the role, emit none of these.

Accessory-label slot: recipe `AccessoryLabelSlot { enabled, position_band }` carries INTENT only. Per 85-CONTEXT.md the LABEL TEXT stays Gemini's (Phase 82 `accessory_label`). So applyLayoutRecipe must NOT write `accessory_label` text. The post-process responsibility here is limited to: nothing structural is forced — the band intent is conveyed via the prompt (Task 2). Add an explicit comment in this module that `accessory_label` text is intentionally never written by applyLayoutRecipe (it is Gemini-authored). Do NOT introduce a new slide field for the band.

Accent rhythm: `recipe.accent_cadence` is a PROMPT hint only (Task 2) — applyLayoutRecipe does NOT force `hook_segments` positions. Add a comment noting this.

Closed-enum invariant: import the band tuples/types from `@/lib/types/layout-recipe` (HOOK_POSITION_BANDS etc.) — do NOT redefine enum string literals. The two Record<> resolver tables are keyed by the imported union types so a new band value is a compile error.

Zero new slide/render fields — only write into existing `SlideStyleOverrides` keys listed above. The `slide-zero-new-fields` test must stay green.
