## What "UI" Means In This Phase

This phase ships THREE distinct visual identities, not three React components. Each identity is a `SlideTemplate` config object (per-template typography, color, spacing, layout primitives) that the existing renderers consume. The contract below is therefore a **visual identity contract** for each template, not a component-library contract.

The only **app-shell** UI surface is the `/templates` picker tile — and that surface ALREADY exists and auto-extends from the `templates` array. No new picker code is written in Phase 56; the regression test merely asserts that the 3 new tiles render their PNG thumbnails (no swatch fallback).

## Decorative Overlay Asset Specifications

### Inventory (TPL-04 — 14 assets total: 12 SVG + 2 PNG)

All assets live in `public/overlays/`. SVG preferred for vector overlays; PNG required for halftone (raster grain quality).

| Asset filename | Format | Pixel dimensions (viewBox) | Visual identity |
|---|---|---|---|

| `sticky-note-pink.svg` | SVG | 240×240 | Pink Post-it, slight rotation, soft shadow |

| `arrow-down.svg` | SVG | 120×120 | Hand-drawn-style downward arrow |
| `arrow-left.svg` | SVG | 120×120 | Hand-drawn-style left arrow |
| `arrow-right.svg` | SVG | 120×120 | Hand-drawn-style right arrow |
| `polaroid-frame.svg` | SVG | 480×600 | White Polaroid frame, thicker bottom caption strip, soft drop shadow |
| `paper-torn-edge.svg` | SVG | 1080×60 | Jagged torn-paper top edge, matches paper-cream fill |

### Authoring rules (per CONTEXT D-15 / D-16)
- **In-house authored.** No third-party licensed sets. Hand-written SVG path data OR programmatic generation via planner-discretion `scripts/build-overlays.ts`.
- **Stroke style** for arrows: 4-6px stroke, slight wobble (achieved via 3-4 anchor-point Bezier with offset control points to feel hand-drawn — NOT perfectly geometric).
- **Fill colors locked** per the asset color table above.
- **Drop shadows on sticky notes / polaroids:** `feDropShadow` SVG filter at `dx=4 dy=8 stdDeviation=4 flood-color=#000000 flood-opacity=0.15`. Permitted because these are SVG `<filter>` elements applied INSIDE the SVG, not CSS `filter:` properties on the rendered `<img>` (Satori compatible — SVG filters work; CSS filter properties do not).
- **Rotation** is applied at OVERLAY-INVOCATION time via `template.overlays[i].content.rotation` (Phase 56 `OverlayContent` extension), NOT baked into SVG. This way the same `tape-strip-1.svg` can rotate -8° on slide 1 and +12° on slide 2 of the same carousel.

## Grain PNG Asset Specifications (TPL-05)

All assets live in `public/textures/`. Generated deterministically via `scripts/build-textures.ts` (CONTEXT D-17..D-19).

| Asset filename | Dimensions | Generation params (locked) | Render opacity (Phase 55 D-11) |
|---|---|---|---|
| `grain-subtle.png` | 1080×1920 | Gaussian noise σ=0.04, low-pass blur radius=1 | 0.04 |
| `grain-medium.png` | 1080×1920 | Gaussian noise σ=0.08, low-pass blur radius=1 | 0.08 |
| `grain-heavy.png` | 1080×1920 | Gaussian noise σ=0.14, ramped contrast +20% | 0.14 |
| `paper-texture.png` | 1080×1920 | Base #F4EFE3 + low-frequency noise (radius=12 blur) + 5-10 hand-placed darker fiber streaks | 0.18 |
| `xerox-grain.png` | 1080×1920 | High-contrast B&W noise + median filter for blocky photocopier feel + threshold ~0.5 | 0.22 |

**Determinism contract:** `npm run textures` invoked twice → byte-identical PNGs (SHA-256 verified). Test asserts via `scripts/build-textures.test.ts` (CONTEXT D-18).

**Rendering pathway:** Satori and React DOM both consume via `renderGrain(intensity)` exported from `resolve-overlay.ts` (Phase 55, D-09..D-13). No `<canvas>` runtime generation; static PNG only.
