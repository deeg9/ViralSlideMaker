## Spacing Scale

Slide canvas spacing tokens (1080×1920 reference space, integer pixels). Multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Pill vertical padding (`4px` top/bottom on highlight pills) |
| sm | 8px | Pill marginRight (breathing room between consecutive pill segments); pill `borderRadius` |
| md | 12px | Pill horizontal padding (`12px` left/right on `'pill'` style) — also block style horizontal padding could collapse here, but block uses 8px (see exceptions) |
| lg | 60px | Slot inset from canvas edge for `top-left` and `top-right` overlay slots — matches Murphy reference visual breathing room |
| xl | 80px | `bottom-card` inner padding (matches Murphy reference card breathing room); also default left-aligned hook/body inset inside the card |
| 2xl | n/a | not used in this phase |
| 3xl | n/a | not used in this phase |

### Exceptions (locked by 45-CONTEXT.md, all multiples of 4)

| Value | Rationale |
|-------|-----------|
| `padding: 4px 8px` (block style) | `'block'` highlight style uses tighter horizontal padding than `'pill'` (locked: pill = 4/12, block = 4/8) |
| `padding: 4px 12px` (pill style) | locked Area 2 default for `highlightStyle: 'pill'` |
| `borderRadius: 8px` (pill) / `0` (block) | locked Area 2 default — pill is rounded, block is squared |
| `bottom-card` height ≈ 730px (38% of 1920) | locked Area 3; matches Murphy reference card proportions |
| Background tint full-bleed (0 inset) | `position: absolute; inset: 0` over the photo, before bottom-card |
| Free-tier watermark spacing | governed by existing `resolveForcedWatermark` — Phase 45 does not modify |

## Typography

Phase 45 does **not** introduce new type sizes; it consumes the existing template type scale (`template.hookFontSize`, `template.bodyFontSize`, `template.fontFamily`, `template.headingFontFamily`) and the existing `news-hook-fit` auto-shrink helper. The values below describe **only the new overlay-text contract** introduced by this phase.

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Overlay chip text (`top-left`, `top-right`, `mid` slots) | from `TemplateOverlay.style.fontSize` (template-declared, default fallback `28px` if absent) | from `TemplateOverlay.style.fontWeight` (default `700`) | `1.0` (single-line chip) | `45-CONTEXT.md` Area 1 + `TemplateOverlay.style` schema |
| Page-counter text | inherits overlay chip rules — driven by `template.overlays[i].style` for the counter slot | same | `1.0` | TPLREND-03 |
| Hook text (inside bottom-card) | unchanged from `template.hookFontSize` (auto-shrunk via `news-hook-fit` for long copy) | `900` (existing) | `1.1` (existing) | existing renderer |
| Body text (inside bottom-card) | unchanged from `template.bodyFontSize` | `400` (existing) | `1.5` (existing) | existing renderer |
| Highlight pill text run | inherits surrounding hook/body type — pill only adds `backgroundColor + padding + borderRadius`, never overrides type | n/a | n/a (rendered inline within hook/body) | locked Area 2 |

### Phase 45 Typography Rules (additive)

1. **No new font families introduced.** All text in this phase uses fonts already loaded by existing templates.
2. **No `text-transform` mutation by the renderer.** `textTransform` only applies if explicitly declared on `TemplateOverlay.style.textTransform` (a closed enum: `uppercase | lowercase | capitalize | none`) — the renderer never silently uppercases overlay content.
3. **Heading font fallback rule preserved:** hook uses `template.headingFontFamily ?? template.fontFamily`. Phase 45 does not change this resolution.

## Color

Phase 45 does **not** introduce a global color palette; per-slide colors come from the `SlideTemplate` config and the per-segment `highlightColor`. The 60/30/10 mapping below describes how colors compose **on the slide canvas** for new-style (image-bleed / image-with-bottom-card) templates.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slide.background_url` photo (full-bleed cover) when `backgroundMode === 'image-bleed'` or `'image-with-bottom-card'`; falls back to `template.backgroundColor` flat fill when `backgroundMode === 'color'` | The visual surface of the slide |
| Secondary (30%) | `template.backgroundColor` rendered with alpha `0.85` (rgba) for the `bottom-card` overlay when `backgroundMode === 'image-with-bottom-card'`; or `template.overlayColor × overlayOpacity` tint when `image-bleed` | Card / tint surface that hosts hook & body text |
| Accent (10%) | per-segment `TextSegment.highlightColor` (the mint pill in Murphy reference) | Reserved for **per-word emphasis pills only** — renderer never applies it elsewhere |
| Destructive | n/a | No destructive UI in this phase |

### Accent reserved-for list (locked)

The accent — the per-segment highlight pill color — is rendered **only** in these positions:

1. Inline `<span>` background behind a `TextSegment` whose `highlightColor` is set, when emitted by the hook text run (`renderSegmentChildren` for `slide.hook_text` + `slide.hook_segments`).
2. Inline `<span>` background behind a `TextSegment` whose `highlightColor` is set, when emitted by the body text run (`renderSegmentChildren` for `slide.body_text` + `slide.body_segments`).
3. Inline `<span>` background behind a `TextSegment` whose `highlightColor` is set, when emitted inside a `CustomText` block (`renderSegmentChildren` for `ct.text` + `ct.segments`).

The accent is **never** used by Phase 45 for: overlay chip backgrounds (those are template-config), page-counter backgrounds, button states (no buttons), focus rings (no focusable canvas elements), or borders.

### Color rules for this phase

| Rule | Locked value | Source |
|------|--------------|--------|
| Bottom-card alpha when `template.backgroundColor` is a 6-digit hex | `0.85` (rgba) | `45-CONTEXT.md` Area 3 |
| Bottom-card alpha when `template.backgroundColor` is an 8-digit hex | uses the embedded alpha as-is | `45-CONTEXT.md` Area 3 |
| Tint overlay color | `template.overlayColor × overlayOpacity` | preserves existing renderer behavior |
| Highlight pill default style | `'pill'` (rounded) when `highlightStyle` undefined; `'block'` (squared) when explicitly set | derived from Phase 44 schema + Area 2 |
| `TextHighlightEffect` (per-text-effect) coexistence | unchanged — operates on a separate layer; per-segment pills do **not** replace it | `45-CONTEXT.md` specifics |

## Slot Geometry (locked design tokens)

Pixel anchors on the 1080×1920 reference canvas. Both render paths import from the same shared constant.

| Slot | Anchor | Behavior | Source |
|------|--------|----------|--------|
| `top-left` | `(60, 60)` from top-left | Single-line chip; honors `TemplateOverlay.offset.{x,y}` as additive nudge; honors `TemplateOverlay.style.padding/borderRadius/etc.` inline | 45-CONTEXT.md Area 1 |
| `top-right` | `right: 60, top: 60` (uses CSS `right` not computed `left: W-60` so Satori absolute positioning works correctly) | Single-line chip; honors `offset` and `style` | 45-CONTEXT.md Area 1 + specifics |
| `mid` | horizontally centered, `y ≈ 55%` of canvas height (i.e. `top: pxY(55)` with `transform: translateX(-50%)` or `left: 50%` flex centering) | Mid-card pill (the "TR3NDING" pill above headline); honors `offset` and `style` | 45-CONTEXT.md Area 1 |
| `bottom-card` | full width, height `pxY(38)` ≈ 730px, anchored at `bottom: 0`, `padding: 80px` inside | Card surface; hook + body text fall back to a card-aware preset when this slot is active (left-aligned, bottom-anchored inside the card); user `style_overrides.text_position/hook_position/body_position` still win | 45-CONTEXT.md Area 1 + Area 3 |
| `free` | no auto-positioning | `TemplateOverlay.offset.{x,y}` becomes absolute `(left, top)` pixel coordinates directly | 45-CONTEXT.md Area 1 |

### DOM Layer Stack (Satori has no z-index — order is contract)

Locked rendering order for `image-bleed` and `image-with-bottom-card` modes:

1. Background photo (full-bleed cover)
2. Tint overlay (`template.overlayColor × overlayOpacity`)
3. Bottom card (only when `image-with-bottom-card`)
4. Overlays (chip, counter, mid pill) — above tint, **below** main hook so headline pills stay top-most
5. Hook text (with mint highlight pills as inline `<span>`s)
6. Body text
7. `slide.custom_images`
8. Brand watermark (existing `resolveWatermark`)
9. Forced free-tier watermark (existing `resolveForcedWatermark`)

For the legacy `backgroundMode === 'color'` path (or undefined → 5 existing templates), order is unchanged from current renderer.

Per-`TextSegment` pill rendering — the mint-pill aesthetic from the Murphy reference. Both render paths must emit identical `<span>` markup.

| Property | `'pill'` (default) | `'block'` | Source |
|----------|--------------------|-----------|--------|

| `borderRadius` | `'8px'` | `'0'` | locked Area 2 |
| `marginRight` (separator) | `'8px'` after the segment for breathing room | `'8px'` | locked Area 2 |

### Parity Gotcha (must be commented in code)

**Browsers support `box-decoration-break: clone` but Satori does not.** React preview must explicitly **NOT** set this property — even though the multi-line break would look prettier in DOM, parity with the exported PNG is the contract (TPLREND-05). Document this as an inline comment in `src/components/slides/slide-preview.tsx` at the highlight-pill render site.

## Background Composition Modes

| Mode | Visual contract | Composition |
|------|----------------|-------------|
| `'color'` (default / undefined) | Existing flat-fill behavior. Zero behavior change for the 5 existing templates (`highlight-bar`, `news-drop`, `news-cyan`, `y2k-pop`, `bold-yellow`). | Photo (if any) renders inside `NEWS_LAYOUT` zone or as full-bleed CSS `backgroundImage`; flat color fills the rest. |
| `'image-bleed'` | Photo full-bleed under everything (1080×1920 cover, top:0 left:0). Tint overlay paints above using `template.overlayColor × overlayOpacity`. | Layers 1 → 2 → 4..9 (no bottom-card). |

### Mutual Exclusion Rule (locked)

`style_overrides.layout` (legacy `NEWS_LAYOUT` cover/body) and `template.backgroundMode` are mutually exclusive.

Resolution order:
1. If `style_overrides.layout` is set → legacy `NEWS_LAYOUT` path wins (legacy news templates unchanged).
2. Else if `template.backgroundMode` is set → new path runs.
3. Else → current flat-color behavior.

**Existing 5 templates leave `backgroundMode` undefined → zero behavior change. This is the regression-safety contract.**

## Render Context Contract (preview/export parity)

New optional `ctx` parameter threaded through both render paths. Guarantees a single shared resolver (`resolveOverlayContent`) computes overlay content for both Satori and React.

### Satori entry (server-side)

```ts
buildSlideElement(slide, template, brandKit, tier, origin, ctx?)

ctx = {
  slideIndex: number    // 0-based array index
  totalSlides: number   // length of the carousel
  topic?: string        // from project.topic
}
```

Callers (`render-slide.ts`, `/api/v1/projects/[id]/render`, `/api/v1/projects/[id]/download`, MCP `render_carousel` if/when re-introduced) pass the array index and length they already iterate over, plus `project.topic` from their existing data fetch.

**Graceful fallback:** Callers that omit `ctx` render counter as `1/1` and resolve `slide-field` to empty string. No thrown errors — keeps legacy callsites green.

### React preview (client-side)

`<SlidePreview>` props extended:

```ts
slideIndex?: number    = 0
totalSlides?: number   = 1
```

Editor callsites (`slide-canvas.tsx`, `slide-grid.tsx`, `slide-list.tsx`, plus `/explore/[slug]` slideshow already iterating slide arrays) pass the array index and length.

### Shared resolver

```ts
// src/lib/render/resolve-overlay.ts
export function resolveOverlayContent(
  content: OverlayContent,
  ctx: { slideIndex: number; totalSlides: number; topic?: string; slide: Slide }
): string
```

Both render paths call this with the same `ctx` → guarantees zero drift on:

- `'page-counter'` format string parsing (default `'{currentSlide}/{totalSlides}'`).
- `'slide-field'` lookup (closed enum: `topic` from ctx, `hook_text` / `body_text` from `ctx.slide`).
- `'literal'` passthrough (returns `content.text` verbatim).

## Copywriting Contract

Phase 45 introduces no new chrome UI copy (no buttons, no error toasts, no empty states). The "copywriting" surface in this phase is **dynamic content rendered into overlay slots** — and the contract for that is parsing rules, not prose.

| Element | Rule |
|---------|------|
| Page counter format string | Default `'{currentSlide}/{totalSlides}'` when `OverlayContent.format` is undefined. Renderer must support `{currentSlide}` and `{totalSlides}` substitution tokens (literal braces around the variable name). Unknown tokens passthrough verbatim (defensive — Phase 44 validator already rejects unknown tokens at module load). |
| Empty `slide-field` value | Empty string (no fallback prose) — the Phase 47 prompt-tuning phase is responsible for ensuring `topic`, `hook_text`, and `body_text` are non-empty. Renderer does not invent content. |
| Empty carousel (totalSlides = 1, slideIndex = 0) | Counter renders as `'1/1'` (literal) — no special-case "no counter" suppression. |
| Pill text run with empty `segment.text` | Renderer emits a zero-width `<span>` (existing behavior preserved) — does not collapse the pill. Phase 47 prevents empty segments at generation time. |
| Watermark text | Unchanged — driven by existing `resolveForcedWatermark` and `resolveWatermark`. Phase 45 does not touch. |
| Error state copy | n/a — this phase has no user-visible error surface. Render failures bubble through existing API error paths. |
| Destructive action copy | n/a — no destructive actions introduced. |
| Primary CTA | n/a — no chrome introduced. |

### Render-failure behavior (locked, code-level)

| Condition | Behavior |
|-----------|----------|
| `template.overlays` undefined | Renderer skips the overlay block entirely (zero layers added). Legacy templates unchanged. |
| `template.backgroundMode` undefined | Renderer skips new background composition; legacy path runs. |
| `ctx` omitted by Satori caller | Counter resolves to `'1/1'`; `slide-field` resolves to `''`. No throw. |
| `slideIndex` < 0 or `≥ totalSlides` | Treated as graceful — counter still renders `{slideIndex+1}/{totalSlides}` (no clamping). Phase 44 validator + Phase 47 prompts prevent malformed inputs. |
| `segment.highlightColor` is invalid CSS | Browser/Satori falls back to transparent (existing CSS behavior). No runtime validation in Phase 45. |
