       - Export async function startStdioServer():
         - Create server = new McpServer({ name: "viralslidemaker", version: "1.0.0" })
         - Call registerTools(server)
         - Create transport = new StdioServerTransport()
         - await server.connect(transport)
         - Log to stderr (not stdout -- stdout is for JSON-RPC): `console.error("ViralSlideMaker MCP server running on stdio")`
       - IMPORTANT: For stdio transport, the tools that need auth will need the API key passed differently.
         Since stdio doesn't have HTTP headers, the tools should check for VIRALSLIDEMAKER_API_KEY env var as fallback when extra.authInfo is not available.
         Add a note in the file: tools read userId from authInfo (HTTP) or from env-based auth (stdio).
         In stdio mode, before connecting, set up auth by reading VIRALSLIDEMAKER_API_KEY from process.env, validating it against the DB (same hash+lookup as verifyMcpToken), and storing the resolved userId.
         Use server.server.setRequestHandler or pass auth context through a module-level variable that tools can read.
         SIMPLER APPROACH: Since mcp-handler's withMcpAuth is HTTP-only, for stdio transport we authenticate once at startup:
         - Read VIRALSLIDEMAKER_API_KEY from env
         - Hash and look up in DB to get userId
         - Store userId in a module-level variable
         - Tools check extra.authInfo?.extra?.userId first (HTTP path), then fall back to the module-level userId (stdio path)

| stdio server -> REST API | HTTP requests with Bearer token to deployed app |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
