<objective>
Make a selected DB template id survive generation (WIRE-02). Today the
category-snap logic in `generation-form.tsx`, `project/[id]/actions.ts`, and
`services/carousel.ts` discards any id not in the code-only
`categoryModule.templateIds` array — silently snapping a DB id to the category
default. This plan makes the snap DB-aware: a DB template id whose row
`category` matches the selected category is kept; only a genuinely
cross-category id snaps.

Also:
- `/api/v1/carousel` adds an `isKnownTemplateId` check rejecting an unknown id
  with HTTP 400.
- `carousel.ts`'s sync `getTemplate(effectiveTemplateId).backgroundMode` call
  becomes async `resolveTemplate` — the snap fix newly lets a DB id reach it,
  and the sync code-only lookup would read `backgroundMode` off the wrong
  template (`templates[0]`).
- A small registry helper `templateCategory(id)` gives the server-side snap
  the DB row's category.

Depends on Plan 01's `getPickerDbTemplates` / `PickerDbTemplate`.
</objective>
