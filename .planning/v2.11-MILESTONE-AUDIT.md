### End-to-End Flows Verified

A. ✓ Multi-select via marquee → align via toolbar → undo (one step)
B. ✓ Group 3 elements (Cmd+G) → drag group → ungroup (Cmd+Shift+G) → positions preserved
C. ✓ Lock element → marquee skips → alignment includes in bounds but doesn't move → unlock
D. ✓ Layers panel: click chip → element selected on canvas → toggle visibility → both renderers honor
E. ✓ Alt+drag selection → duplicates appear; originals stay; new groupId for duplicate set
F. ⚠ Arrow nudge → updates lastMoveDelta → Cmd+D uses smart offset matching last nudge — **PARTIAL**: Cmd+D dispatches `ADD_TEXT_BOX` (creates new blank custom text at offset), NOT `DUPLICATE_ELEMENTS_AT` of current selection. Smart-offset behavior works as specified; multi-element duplicate-of-selection semantic is an open spec gap (REQ DIFF-02 wording vs. impl).

## Documented Gaps (deferred to v2.12+)

These are explicit design decisions documented in their respective Phase SUMMARYs:

| # | Gap | Source | v2.12+ Disposition |
|---|---|---|---|
| 1 | **Watermark freeform position** — BULK_TRANSLATE/ALIGN/DUPLICATE_ELEMENTS_AT skip watermark; `position` is enum-only (top-left/bottom-left/bottom-right). Multi-select including watermark silently leaves it behind during group drag. | Plan 60-03 | Schema lift watermark `position` to numeric x/y; freeform drag and align participation |
| 2 | **Cmd+D duplicate-of-selection semantics** — Cmd+D currently creates a new blank custom text at smart-offset; REQ DIFF-02 wording implies multi-element duplicate. lastMoveDelta plumbing is correct. | Plan 66-01 design intent | Re-spec: rebind to DUPLICATE_ELEMENTS_AT or add a separate Cmd+Shift+D shortcut |
| 3 | **Alt+drag does not auto-select duplicates** — Originals stay selected after duplicate completes. Differs from Figma default (selects copies). | Plan 66-02 v2.11 simplification | Reducer returns new ids OR slide-diff in dispatch wrapper |
| 4 | **TextBox alignment height = 0** — DOM-ref measurement deferred. Center-v / bottom alignment of text snaps to top edge. | Plans 60-05, 63-01 | Lift DOM-ref height into pure helper via measurement hook |
| 5 | **Layers panel drag-to-reorder (PERF-02)** — Vanilla panel uses button-based reorder only (Cmd+]/[ ); drag deferred due to react-arborist + React 19 StrictMode + react-dnd@14 risk | Plan 65-01 design choice | Re-evaluate react-arborist 3.5+ once StrictMode cleanly verified, OR build DIY @dnd-kit/sortable |

## Cross-Cutting Invariants Preserved

1. **TPLREND-05 byte-identity** — every editor-only feature (selection rings, marquee rect, smart guides, group bbox, alignment toolbar, layers panel, lock-icon overlay) gates behind `editable={true}` structurally; PARITY-01..05 audit suite has TEETH (chrome-leak scan + 11-template fingerprint suite + v2.9/v2.10 regression sweep)
2. **Single pushHistory per gesture** — every multi-element reducer case (BULK_TRANSLATE, ALIGN, DISTRIBUTE, GROUP, UNGROUP, SET_LOCKED, SET_HIDDEN, Z_ORDER, DUPLICATE_ELEMENTS_AT) calls `pushHistory` exactly once
3. **onDragStop-only dispatch** — never per-tick `onDrag`; carry-forward from v2.10 PERF-01
4. **isEditing keyboard guard** — every new tinykeys binding wraps body in `if (isEditingTarget(e.target)) return; e.preventDefault(); ...` — final firewall count: 33 inline + 8 helper-consolidated
5. **Modifier-state-resets-on-blur** — `useModifierState` listens to `window.blur` + `document.visibilitychange`
6. **Selection state outside reducer history** — `useSelectionModel` is React state only; never dispatched
7. **Z-order = array splice** — never CSS `z-index`; `applyDualWrite` propagates to legacy projection; both renderers iterate in array order
8. **Both renderers byte-identical** — symmetric `hidden`/`watermark`/`groupId` handling at every iteration site
