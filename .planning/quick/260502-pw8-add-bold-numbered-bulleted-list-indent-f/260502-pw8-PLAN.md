# Plan: Bold (per-segment) + numbered/bulleted lists + indent for slide-editor text boxes

## Context

User asked for Word/Figma/Canva-style formatting on slide text boxes: bold, numbered/bulleted lists, indents. Research (`260502-pw8-RESEARCH.md`) confirmed:

1. **Box-level Bold already ships** at `ActiveTextBoxCard.tsx:199-214` (toggles `text_box.font_weight: 700`).
2. **No list / indent / per-segment-bold concept** exists in the schema.
3. **Satori's CSS subset** disallows `<ol>`, `<ul>`, `display: list-item`, `::marker` — the canonical workaround is rendering markers as literal text (`1. `, `• `) in a `flex-direction: column` container with one child `<div>` per line. That's what we do.
4. **Phase 60-05 collision risk:** light. Different regions of `slide-preview.tsx`. User chose ship-now.

User locked: per-segment Bold + verify box-level + lists + indents, ship now.

## Approach

**Schema is paragraph-level for lists/indent, segment-level for bold** — mirrors Figma's TextListOptions + TipTap's leaf-marks pattern.

- `bold?: boolean` on `TextSegment` (new mark, parallel to existing `accent?: boolean`).
- `list_type?: 'numbered' | 'bulleted'` on `TextBox` and `CustomText`. Omitted = plain text. No `'none'` literal — `undefined` is the off state.
- `list_indent?: number` on `TextBox` and `CustomText`. Levels 0/1/2 (clamped). Each level = 32px padding-left at reference 1080×1920 size.

**Renderer:** new `renderTextBlock(text, segments, listType, listIndent, baseColor, accentColor)` helper in `resolve-overlay.ts`. Splits text on `\n`, prepends `${i+1}. ` (numbered) or `• ` (bulleted) to each line, indents via `paddingLeft`. **When `listType` is undefined AND `listIndent` falsy, returns `renderSegments(...)` byte-identically** so legacy text boxes (zero behavior change) stay unchanged → preserves TPLREND-05 parity for every slide that doesn't opt into lists.

**v1 limitation (documented):** segments are flat across the whole text — when `listType` is set, each line renders as plain text (no per-segment color/bold/highlight inside list items). Per-segment styling _within_ list items is a v2 follow-up. Acceptable: users typing a numbered list don't expect rainbow-highlighted bullets.

**Per-segment Bold UI:** mirror `AccentWordsDisclosure` → new `BoldWordsDisclosure` component. Same chip-toggle UX. Existing box-level Bold button stays as-is (mass-bold the entire box).

**List + Indent UI:** segmented control + indent buttons in `ActiveTextBoxCard.tsx`, near the existing Style row.

/** quick-260502-pw8: per-segment bold mark. When true, segment renders at fontWeight 700 regardless of the parent text-box's font_weight. */

### Task 2 — Renderer support

**Files:** `src/lib/render/resolve-overlay.ts`, `src/lib/render/render-slide-satori.tsx`, `src/components/slides/slide-preview.tsx`

In `resolve-overlay.ts`:
1. Extend `renderSegments` to honor `seg.bold` — when true, span gets `fontWeight: 700`.
2. Add `renderTextBlock(text, segments, listType, listIndent, baseColor, accentColor)`:
   - Fast path: if `!listType && !listIndent` → return `renderSegments(text, segments, baseColor, accentColor)` (byte-identical).
   - List path: split text on `\n`, render each line as a child div with `paddingLeft: (listIndent ?? 0) * 32` and inline marker prefix (`${i+1}. ` or `• ` followed by NBSP-padded line text). Wrapper is `display:flex; flexDirection:column; width:100%; gap:8px`.

In `render-slide-satori.tsx`:
- Update the 3 `renderSegmentChildren` call sites (hook, body, custom_texts at lines 437/446/511) to use a new `renderTextBlock` wrapper that reads `text_box.list_type` / `text_box.list_indent` (or the legacy hook/body equivalents).
- Pass `list_type` / `list_indent` through. For `hook_segments` / `body_segments` legacy paths, `list_type` always undefined → fast-path returns byte-identical.

In `slide-preview.tsx`:
- Mirror the same wiring at the editor-side render call sites for hook/body/custom_texts. Same import from `resolve-overlay.ts`.
