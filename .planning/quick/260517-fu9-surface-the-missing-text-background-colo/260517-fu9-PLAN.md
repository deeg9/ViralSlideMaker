<objective>
Surface the existing **text background color** control under the **Elements** tab of the
slide editor.

**Investigation result — the control ALREADY EXISTS; it is just on the wrong tab.**

The "background fill rendered behind a text element" is the `highlight` text effect.
It is fully built and working:

- Data model: `TextHighlightEffect` — `src/lib/types/slide.ts:104-114`
  (`{ enabled, color (8-digit hex w/ alpha), style: 'tight'|'full', padding }`),
  stored on `TextBox.effects.highlight` (`slide.ts:152`).
- UI control: the `HighlightControls` sub-component +
  `<EffectRow label="Highlight">` — `src/components/editor/text-rail/ActiveTextBoxCard.tsx:589-599`
  and `:741-821`. It renders a 4-swatch color row + native `<input type="color">`
  palette opener (`data-testid="highlight-color-row"`), a Tight/Full toggle,
  and a padding slider.
- Render: consumed identically by canvas (`slide-preview.tsx:1186`, `:1207`) and
  PNG export (`render-slide-satori.tsx:99-104` `satoriHighlightStyle`) — TPLREND-05
  parity holds by construction.

**Why the user sees green with no control:** the active text box has a *stored*
`highlight.color` value (AI-emitted or template-derived). There is no literal green
default in code (`DEFAULT_HIGHLIGHT.color = '#00000088'`, `ActiveTextBoxCard.tsx:54-59`).
The control that edits this field lives ONLY under the **TEXT** tab inside
`ActiveTextBoxCard` (mounted via `text-editor-panel.tsx:125`). The **Elements** tab
(`elements-panel.tsx`) has Icons & Shapes / Lines & Dividers / Caption Bar / Watermark
sections — and no text-background control. So the user, looking under Elements, sees
the green fill but no way to edit it.

**The fix:** extract `HighlightControls` into a small reusable component and mount it
as a "Text Background" portlet card under the Elements tab (visible when a text box is
the active selection). REUSE the existing control — do NOT build a new color picker.
Keep it under the TEXT tab too (no regression).

Purpose: give users a discoverable place to recolor the fill behind a text box from
the Elements tab, where they expect element styling to live.
Output: a reusable `TextBackgroundControls` component + a new Elements-tab card wired
through `slide-editor`.
</objective>
