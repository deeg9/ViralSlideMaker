<objective>
Add 8-handle resize and centering-guide snap to icons and shapes on the slide-editor canvas, matching how text boxes and custom images already behave. Today the editable decoration `<Rnd>` block in `slide-preview.tsx` supports drag only — `enableResizing={false}` and the drag handlers never touch the snap engine.

This is a wiring task, not a new system. The shared snap engine (`snap-index.ts`, `runSnapForDrag`) is pure and element-type-agnostic; the reducer's `UPDATE_DECORATION` already shallow-merges a full `{x,y,width,height}` position; decorations already carry `width`/`height`. The decoration `<Rnd>` block simply isn't calling the shared machinery. We make it call the SAME functions the custom-image block calls — no parallel implementation.

Purpose: Icons/shapes become first-class editable elements (resize + alignment), removing a glaring inconsistency where only text/images can be sized and snapped.
Output: Decoration `<Rnd>` block gains resize handles + snap-on-drag; `buildSnapIndex` makes decorations snap targets; a new `onDecorationSizeChange` callback threads the resize commit through to `UPDATE_DECORATION`.
</objective>
