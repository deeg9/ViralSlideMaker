<objective>
Make watermark changes project-wide. Today, toggling the "Show watermark" Switch, picking a position, uploading a custom logo, or removing a custom logo only affects the active slide — every other slide in the project keeps its previous watermark state. Diego's screenshot confirmed this on the paid tier: clicking the toggle flips the Switch immediately (sister fix quick-260502-fai works) but the watermark only renders on slide 1; slides 2..N still show the previous state until each is individually re-toggled.

The user's expectation: "If a user clicks the show watermark button, then it should be applied to all slides." Same for position, custom-logo upload, custom-logo remove. The watermark is conceptually a project-level setting, not a per-slide setting.

Picked architecture (Option A — broadcast, NOT a project-table refactor):
1. **Server:** new `updateProjectWatermark(projectId, patch: WatermarkSpec)` that loads the project, iterates every slide's `style_overrides.watermark`, merges `{ ...existing, ...patch }` into each, and writes back the entire `slide_data` array in one update. Same auth + paid-tier guard as `updateSlideWatermark`.
2. **Client:** the three watermark handlers in `slide-editor.tsx` build a new `slides[]` array client-side (mirroring the server's merge), dispatch `SET_SLIDES` (ONE history entry, so Cmd+Z reverts the whole broadcast), and call `updateProjectWatermark(projectId, spec)` inside `startWatermarkTransition`.
3. **Drop** `updateSlideWatermark` from `editor-actions.ts` and from the test mocks — repo-wide grep confirms only the three handlers (we're rewriting) and the test files (we're rewriting) consume it.

Why broadcast beats a project-table refactor: zero migration, no schema change in `projects`, no new server-side aggregation logic, and the per-slide JSONB already flows through to every renderer (resolveForcedWatermark / WatermarkLayer / etc. all read per slide). The "project-wide" semantic lives entirely in the writer.

Purpose: Restore the user's mental model. Pre-PMF, the watermark feature looking inconsistent across slides reads as a broken feature.
Output: One new server action + three rewritten client handlers + an updated vitest file (existing 3 cases retargeted to the new mock + 1 new "broadcasts to all slides" case), all behind the existing tier gate.

Out of scope (do NOT touch):
- Free-tier behavior — `resolveForcedWatermark` already renders ViralSlideMaker on every slide regardless of `style_overrides.watermark`. The bug only ever bit paid users.
- Migration to a `projects.watermark_config` column — explicitly rejected per the bug diagnosis.
- `handleSlideTreatmentChange` and the treatment-sync test — those stay per-slide by design (treatments are per-photo, not per-project).
- Hook-position / body-position / photo-treatment broadcast — also per-slide by design.
- The `WatermarkControls` component itself — it correctly emits the spec; we just change what the receiving handler does with it.
- The `currentSlide` hoist at line 91 — still used by `handleSlideTreatmentChange`, leave it in place.
</objective>

    ```ts
    // --- quick-260502-er5 (extended by quick-260502-ik8): project-wide watermark ---

    export type WatermarkSpec = NonNullable<SlideStyleOverrides['watermark']>

    /**
     * Apply a watermark spec patch to EVERY slide in the project (broadcast).
     * The watermark is conceptually a project-level setting; per-slide JSONB
     * is preserved as the storage shape only because that's what the renderer
     * already reads. Server-side tier enforcement (defense in depth — UI gates
     * first):
     *   - free tier: rejected outright (UI disables the controls; defensive).
     *   - paid tier: all fields honored on every slide.
     *
     * Returns the full new slides array on success so the client can sync
     * without a refetch.
     */
    export async function updateProjectWatermark(
      projectId: string,
      patch: WatermarkSpec,
    ): Promise<{ success: true; slides: Slide[] } | { success: false; error: string }> {
      try {
        const supabase = await createClient()
        const {
          data: { user },
        } = await supabase.auth.getUser()
        if (!user) return { success: false, error: 'unauthorized' }

        const tier = await getUserTier(user.id)
        const isPaid = tier === 'plus' || tier === 'pro'
        if (!isPaid) {
          return { success: false, error: 'paid tier required to customize watermark' }
        }

        const { data: project, error: loadError } = await supabase
          .from('projects')
          .select('slide_data, user_id')
          .eq('id', projectId)
          .single()
        if (loadError || !project) {
          return { success: false, error: 'project not found' }
        }
        if (project.user_id !== user.id) {
          return { success: false, error: 'forbidden' }
        }

        const slides = ((project.slide_data ?? []) as unknown) as Slide[]
        const next: Slide[] = slides.map((slide) => {
          const existing = slide.style_overrides?.watermark ?? {}
          return {
            ...slide,
            style_overrides: {
              ...(slide.style_overrides ?? {}),
              watermark: { ...existing, ...patch },
            },
          }
        })

        const { error: saveError } = await supabase
          .from('projects')
          .update({ slide_data: next as unknown as Record<string, unknown>[] })
          .eq('id', projectId)
        if (saveError) return { success: false, error: saveError.message }

        revalidatePath(`/project/${projectId}`)
        return { success: true, slides: next }
      } catch (err) {
        return { success: false, error: (err as Error).message }
      }
    }
    ```
