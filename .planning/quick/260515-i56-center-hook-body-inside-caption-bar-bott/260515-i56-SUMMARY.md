# quick-260515-i56: Center hook + body inside caption-bar-bottom Summary

One-liner: Projector + AI prompt both enforce centered-in-bar y positions for `slideArchetype === 'caption-bar-bottom'` via a single shared constants module (CAPTION_BAR_BOTTOM_HOOK_Y_RANGE / BODY_Y_RANGE / computeCaptionBarBottomPositions).

## What shipped

Two coordinated fixes for the regression Diego flagged on project `ae0ca070-058f-4fe9-85f5-5190b425c6bf`, where caption-bar-bottom slides landed hook y=66.83 / body y=78.57 — both visually outside the dark caption bar (which covers y=62 → y=100).

### 1. AI prompt tightened (belt)

`src/lib/ai/prompts.ts` — the `case 'caption-bar-bottom':` branch in `buildFromSpecPrompt`'s archetype switch was replaced. The vague legacy "set text_position to bottom" guidance is now explicit:

> hook position.y MUST be in range [70, 76]; body position.y MUST be in range [82, 88]. anchor: 'custom'. The hook and body MUST visually sit centered inside the lower caption bar — not at the top edge of the bar.

The literal numbers come from string-interpolation of `CAPTION_BAR_BOTTOM_HOOK_Y_RANGE[0..1]` and `CAPTION_BAR_BOTTOM_BODY_Y_RANGE[0..1]` — no raw 70/76/82/88 literals appear inside the case body (Test 10 grep gate enforces).

### 2. Projector deterministic override (suspenders)

`src/lib/ai/style-spec-projector.ts` — a new archetype-gated branch fires only when `spec.slideArchetype === 'caption-bar-bottom'`:

```ts
if (archetype === 'caption-bar-bottom') {
  const captionSlot = (spec as { caption?: { heightFraction?: number } }).caption
  const { hook, body } = computeCaptionBarBottomPositions(captionSlot?.heightFraction)
  style_overrides.hook_position = { x: hook.x, y: hook.y }
  style_overrides.body_position = { x: body.x, y: body.y }
  style_overrides.hook_width = hook.width
  style_overrides.body_width = body.width
}
```

`computeCaptionBarBottomPositions` returns:

| heightFraction | barTopY | hookY | bodyY |
|----------------|---------|-------|-------|
| 0.38 (default) | 62 | 71.5 | 84.8 |
| 0.4            | 60 | 70.0 | 84.0 |

Both inside the published [70, 76] / [82, 88] bands. The `hook_position` / `body_position` keys flow through `legacyToTextBoxes` (text-box-adapter.ts:31-46 / 48-64) which yields `anchor: 'custom'` — exactly what `separateOverlappingTextBoxes` (260515-8xx) needs to see for the boxes to participate in the layout pass.

### 3. Single source of truth

`src/lib/ai/style-spec-projector-constants.ts` (NEW) exports five constants + one pure function:

- `CAPTION_BAR_BOTTOM_DEFAULT_HEIGHT_FRACTION = 0.38`
- `CAPTION_BAR_BOTTOM_X = 11`
- `CAPTION_BAR_BOTTOM_WIDTH = 78`
- `CAPTION_BAR_BOTTOM_HOOK_Y_RANGE = [70, 76] as const`
- `CAPTION_BAR_BOTTOM_BODY_Y_RANGE = [82, 88] as const`
- `computeCaptionBarBottomPositions(heightFraction?) → { hook, body }`

5 distinct files reference the constants (constants def + projector + prompt + 2 test files). The numbers can never drift between the AI guidance and the projector enforcement because they read from the same exported tuples.

### 4. Type-level discipline preserved

`src/lib/ai/style-spec-projector.types.ts` — `ProjectedSlideOverrides` Pick<> widened to include `hook_position`, `body_position`, `hook_width`, `body_width`. All four fields ALREADY exist on `SlideStyleOverrides` (slide.ts:176-177, 194-195), so STYLESPEC-12 "no new Slide fields" is preserved by construction (the whole point of the structural firewall the types module's own docblock describes).
