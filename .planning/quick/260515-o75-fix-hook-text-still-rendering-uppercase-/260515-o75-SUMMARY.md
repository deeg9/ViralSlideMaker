# Phase quick-260515-o75: Fix Hook Text Still Rendering Uppercase Summary

**Flipped the `resolveHookTypography` textTransform default from template-forced uppercase to `'none'` (WYSIWYG) — a hook text box with a stored lowercase word now renders that word lowercase on the editor canvas, the Satori PNG export, and the HTML render; auto-uppercase is opt-in via the existing "Uppercase" toggle.**

## Performance

## Accomplishments

- Fixed the actual bug the nhf attempt missed: `resolveHookTypography` defaulted `textTransform` to the template's `hookStyle`, so every no-override slide on an uppercase template (`highlight-bar` etc.) was force-capped. The default is now `'none'` — the hook renders exactly as stored. The fix is one initializer line; all three render paths already consume `hookTypography.textTransform`, so the change propagates to canvas, PNG, and HTML simultaneously with no render-path edits.
- Removed the now-dead `templateTransform` const; `template.hookStyle` still feeds the `fontStyle` italic branch so no unused-variable tsc error.
- Inverted the nhf no-override casing assertions in both the resolver unit suite and the render-parity suite to expect WYSIWYG — and added an explicit `highlight-bar` no-override test plus a render-parity bug group (the "...TRUMP'S NEW movie" fixture) that **would have caught the nhf miss**: a no-override slide on an uppercase template renders as-stored.
- The opt-in path is verified intact: a hook TextBox with `text_transform: 'uppercase'` and an `overrides.hook_text_transform` still force-cap across all three render paths.
- Renamed threat `T-nhf-01` → `T-o75-01`: a malformed `text_transform` value falls through to the `'none'` WYSIWYG default — degrades to render-as-stored, never injects CSS.
