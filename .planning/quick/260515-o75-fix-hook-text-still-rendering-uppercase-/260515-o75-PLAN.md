<root_cause>
## Root Cause (verified in code — second attempt)

The first fix attempt (quick-260515-nhf) added the *mechanism* — a `text_transform`
field on `TextBox`, a `hook_text_transform` field on `SlideStyleOverrides`, a shared
`resolveHookTypography` resolver, and an inspector "Uppercase" toggle — but left the
**default behavior unchanged**. That is why the user reports "still not working."

`resolveHookTypography` (`src/lib/render/resolve-overlay.ts:753-782`) computes:

```ts
const templateTransform: 'uppercase' | 'none' =
  template.hookStyle === 'uppercase' ? 'uppercase' : 'none'
let textTransform: 'uppercase' | 'none' = templateTransform   // ← line 761
if (hookTextBox?.text_transform === 'uppercase' || hookTextBox?.text_transform === 'none') {
  textTransform = hookTextBox.text_transform
}
if (overrides?.hook_text_transform === 'uppercase' || overrides?.hook_text_transform === 'none') {
  textTransform = overrides.hook_text_transform
}
```

The user's slide uses the **`highlight-bar`** template
(`src/lib/render/templates/highlight-bar.ts:18`: `hookStyle: 'uppercase'`,
`fontFamily: "'Inter', sans-serif"`, `hookFontSize: '96px'` — matching the inspector's
"Inter / 96"). The user's hook TextBox has **no** `text_transform` field and the slide
has **no** `hook_text_transform` override. So both `if` blocks are skipped and
`textTransform` stays at `templateTransform === 'uppercase'`.

All three render paths consume that value verbatim, so the canvas force-caps the
stored text — including the lowercase word "movie" the user deliberately typed:
- `src/components/slides/slide-preview.tsx:900` — `textTransform: hookTypography.textTransform === 'uppercase' ? 'uppercase' : undefined`
- `src/lib/render/render-slide-satori.tsx:307-308` — `if (hookTypography.textTransform === 'uppercase') hookStyle.textTransform = 'uppercase'`
- `src/lib/render/render-slide.ts:181-182` — `hookTextTransformCss = hookTypography.textTransform === 'uppercase' ? 'text-transform: uppercase;' : ''`

There is **no other uppercase bypass for the hook**. A grep of `src/lib/render` +
`src/components/slides` found `textTransform: 'uppercase'` literals only in
`brutalist-grid.ts:67`, `magazine-bold.ts:56`, and `tr3nding-news.ts:65` — all inside
decoration/segment style blocks, not the hook. The highlight-bar template has no
extra hook styling. All three render paths route the hook exclusively through
`resolveHookTypography`. The `hookTextTransform` field still computed in
`resolve-styles.ts:137` is dead for the hook path — `render-slide.ts:306` emits
`hookTextTransformCss` (from the helper), not `resolved.hookTextTransform`.

**The fix:** flip line 761 so `textTransform` defaults to `'none'` (render the hook
exactly as stored — WYSIWYG) instead of the template's `hookStyle`. The per-TextBox
`text_transform` field and the `hook_text_transform` override (both already shipped
by nhf) become the **opt-IN** for users who explicitly want auto-uppercase, driven by
the nhf "Uppercase" toggle in `ActiveTextBoxCard` which is already wired. Because all
three render paths already consume `hookTypography.textTransform`, flipping the one
default value propagates to the canvas, the PNG export, and the HTML render
simultaneously. No render-path file needs to change.
</root_cause>

## AI-Generation Safety Finding (investigation step 2 — DECISIVE: SAFE)

Inspected the AI hook-text generation path: `src/lib/ai/prompts.ts`,
`generate-slides.ts`, `generate-from-style-spec.ts`, `style-spec-projector.ts`.

**The AI already emits hook text in UPPERCASE for these templates.** Evidence:
- `prompts.ts:30` (news-template branch): `"Keep hook text uppercase-friendly."`
- `prompts.ts:63` (premium-template addendum): the highlight examples are literal
  all-caps strings — `"FIGHTS BACK"`, `"CLONED HER VOICE"`, `"$50M"`, `"12 MINUTES"`.
- The user's stored hook is `THE CHIP WAR JUST GOT REAL: TRUMP'S NEW` — uppercase in
  storage — directly confirming AI-emitted hooks land already-capitalized.
- `style-spec-projector.ts` performs **no** casing transform on hook text; it maps the
  AI's emitted strings through verbatim.
- `highlight-bar` (the affected template) declares **no** `aiVoiceNote`, so its hooks
  come from the generic prompt + the uppercase-leaning premium addendum.

**Conclusion: removing the render-time uppercase default causes ZERO visible change
to AI-generated slides** — they are already stored in caps and will continue to render
in caps (no `text-transform` needed; the characters themselves are uppercase). The
only slides whose appearance changes are ones a human deliberately edited to contain
lowercase characters — which is exactly the intended WYSIWYG fix. **No prompt change
and no generation-time `text_transform` write is required.** The fix is fully safe.
</ai_generation_safety>
