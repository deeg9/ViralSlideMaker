<scope_decision>
This is a UI-only removal. INVESTIGATION CONFIRMED the least-invasive correct path:

1. `style_overrides.layout`, `overlay_opacity`, and `overlay_color` are consumed by
   the renderers in `src/lib/render/render-slide.ts` (lines 175-187) and
   `src/lib/render/resolve-styles.ts` (lines 91-163). Every read uses a sensible
   fallback to the template default (e.g. `overrides.overlay_color ?? template.overlayColor`,
   `Math.round(template.overlayOpacity * 100)`). Removing the controls leaves those
   fields simply unset on new slides — the renderers keep working, and legacy slides
   that already carry these overrides still render exactly as before.

   THEREFORE: DO NOT touch the renderers, the `Slide` / `SlideStyleOverrides` types,
   any Supabase migration, or any `src/lib/render/*` file. Removing data-model code
   would be over-reach and would risk breaking rendering of existing saved projects.

2. The "Slide Settings" card ALSO contains a Watermark hide toggle (rendered only
   when a brand kit has an active watermark — not visible in the user's screenshot).
   That toggle is part of `SlideSettings`, so deleting the component deletes it too.
   This is acceptable: the full `WatermarkControls` card (a SEPARATE component
   mounted right after `SlideSettings`) is the primary watermark surface and STAYS.
   Brand Kit nav is already hidden from production (quick-260515-eey), so the loss
   of the redundant per-slide hide toggle has no real user-facing impact.

3. `src/components/editor/text-editor-panel.tsx` does NOT mount `SlideSettings`
   (it was moved to the Elements tab by quick-260514-move-slide-cards-to-elements).
   Only `elements-panel.tsx` mounts it. No other consumer exists.
</scope_decision>
