## Deviations from Plan

### [Rule 1 — Test setup] Highlight-bar `overlayOpacity` is 0, so a few tests use `news-oracle`

**Found during:** Task 2 write-up (verified against `src/lib/render/templates/highlight-bar.ts:15`).

**Issue:** The plan's `<read_first>` references the existing test helper `TMPL = getTemplate('highlight-bar')` and Test #2 says "highlight-bar's overlayOpacity is non-zero — see the template file." That is no longer true: `highlight-bar.ts:15` ships `overlayOpacity: 0`. With a zero default, `photoOverlayOn` reads `false` for an unedited slide, so the Switch reads UNCHECKED, the slider is NOT rendered, and a few of the planned tests cannot resolve their test ids.

**Fix:**

1. The plan already anticipated this and hedged each affected case ("If it ever changes to 0, the test still asserts the correct branch", "to be robust to any template that ships with overlayOpacity: 0"). I honored the hedges literally:
   - **Test 2** ("Switch reads CHECKED when no overrides + template.overlayOpacity > 0") uses `TMPL_OVERLAY = getTemplate('news-oracle')` (overlayOpacity: 0.45) so the iff-branch can be exercised. The assertion is still computed from `TMPL_OVERLAY.overlayOpacity > 0`, so tuning the template later still flips it to the right branch.
   - **Test 4** ("Slider seeds from `Math.round(template.overlayOpacity * 100)`") also uses `TMPL_OVERLAY`, guarded by `if (TMPL_OVERLAY.overlayOpacity > 0)` so the absent-slider branch is documented if news-oracle is ever tuned to 0.
   - **Test 10** ("falls back to round(template.overlayOpacity * 100) (floored at 1)") uses `TMPL` (highlight-bar). The assertion is `Math.max(1, Math.round(TMPL.overlayOpacity * 100))`, which evaluates to `1` for highlight-bar (matches the `PHOTO_OVERLAY_MIN_PCT_ON` floor in the implementation) and to `round(TMPL.overlayOpacity * 100)` for any non-zero-default template.
2. The plan's test #1 expected a single 'Photo overlay' text node ("`getByText('Photo overlay')` or `getAllByText`"). The implementation renders the string twice (the uppercase section title AND the Switch row label), so the test uses `getAllByText('Photo overlay')` and asserts `length >= 1` — matches the plan's `getAllByText` fallback option.
3. Test #16 prefers `getByRole('switch', { name: 'Photo overlay' })` to disambiguate the duplicate 'Photo overlay' text node from the Switch itself — matches the plan's preferred path.
