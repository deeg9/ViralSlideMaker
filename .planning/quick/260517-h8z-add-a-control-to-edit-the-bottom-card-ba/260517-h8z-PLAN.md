# Quick Task 260517-h8z — Edit the slide background color (the "yellow panel")

## Verified diagnosis (DB-grounded — do NOT re-investigate the root cause)

The user's screenshot is project `cfe4917c-9f68-41b6-8632-79d84c3fb0ba`
("Nvidia Chip Sales to China"), slide at `position: 0`. Production `slide_data`
for that slide:

- `template_id_override`: **undefined** (no per-slide template override)
- `style_overrides.layout`: **`"cover"`**
- `background_url`: a Pexels photo (circuit board)
- project `template_id`: `bold-minimal` (a DEAD id removed in the v2.5 trim;
  `getTemplate()` silently falls back — not in scope to fix here)

Render mechanism (confirmed in code):

- `style_overrides.layout` set + a legacy/non-bgMode template ⇒ the slide is a
  **news-carousel layout** (`newsZone = NEWS_LAYOUT["cover"]`).
- `NEWS_LAYOUT.cover = { imageTop: 0, imageHeight: 55, ... }` — the background
  photo is rendered as a **constrained `<img>`** covering only the **top 55%**
  (`slide-preview.tsx:950-963` `newsBgImageNode`).
- The remaining bottom ~45% shows the slide wrapper's
  `backgroundColor` — `slide-preview.tsx:933` `backgroundColor: template.backgroundColor`.
- **That is the yellow panel the user wants to recolor.** It is hardcoded to
  `template.backgroundColor` in ALL THREE render paths. There is NO
  `style_overrides` field for it and NO editor control for it anywhere.

This is NOT the highlight effect (quick-260517-fu9) and NOT the caption-bar
bottom-card (the original h8z plan). It is the slide background color.

The three render sites that hardcode `template.backgroundColor` for the slide
background:

| Path        | File:line                              | Current code |
|-------------|-----------------------------------------|--------------|
| Editor canvas | `slide-preview.tsx:933`               | `backgroundColor: template.backgroundColor` |
| Satori PNG  | `render-slide-satori.tsx:262-263`       | `rootStyle.backgroundColor = template.backgroundColor` |
| HTML render | `render-slide.ts:209-215`               | `backgroundCss` — `template.backgroundColor` in all 3 branches |

The precedent to mirror exactly: **`overlay_color`** — an optional hex-string
override field added by quick-260515-overlay-color-picker, resolved as
`overrides.overlay_color ?? template.overlayColor` in the same three files
(`slide.ts:184-189`).

## Goal

Add an optional `background_color` override + a "Slide Background" color control
in the editor ELEMENTS tab so the user can recolor that panel. Unset ⇒ falls
back to `template.backgroundColor` (byte-identical legacy rendering, TPLREND-05).
