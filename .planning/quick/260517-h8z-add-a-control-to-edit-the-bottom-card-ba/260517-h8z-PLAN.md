WHAT RENDERS THE YELLOW PANEL
- `src/components/slides/slide-preview.tsx:182-209` — the live editor canvas draws
  the bottom card as an absolutely-positioned `<div data-testid="bottom-card">`
  whose `backgroundColor` comes from `resolveCaptionBar(slide.style_overrides, template)`
  (slide-preview.tsx:189).
- `src/lib/render/render-slide-satori.tsx:405-426` — the Satori PNG export draws
  the identical layer, also via `resolveCaptionBar(overrides, template)` (line 414).
- `src/lib/render/resolve-overlay.ts:380-397` `resolveCaptionBar` — SINGLE source of
  truth. With no overrides → `bottomCardBackground(template.backgroundColor)`
  (byte-identical legacy path). With a `caption_bar_color` override → `hexToRgba(...)`.
- The render gate is `useBottomCard` (slide-preview.tsx:788-789,
  render-slide-satori.tsx:215-216): true iff
  `template.backgroundMode === 'image-with-bottom-card'`.
- The override field already exists: `SlideStyleOverrides.caption_bar_color`
  (`src/lib/types/slide.ts:197`, `// hex with leading '#'; default template.backgroundColor`).

IS IT THE SAME ELEMENT THE CAPTION BAR CONTROL EDITS? — YES.
- `CaptionBarControls` (`src/components/editor/caption-bar-controls.tsx`) writes
  `caption_bar_color` (line 168, 199) — exactly the field `resolveCaptionBar` reads.
  The card edits the yellow panel directly. No new field is needed.

WHY THE CARD IS NOT VISIBLE
- `CaptionBarControls` self-gates: `if (template.backgroundMode !== 'image-with-bottom-card') return null`
  (`caption-bar-controls.tsx:88`).
- `ElementsPanel` mounts it with the per-slide-RESOLVED template:
  `template={resolvePerSlideTemplate(slide, template)}` (`elements-panel.tsx:195`).
- The screenshot slide is a Style-from-Reference `caption-bar-bottom` archetype
  slide. The projector sets `style_overrides.template_id_override = 'magazine-bold'`
  (`src/lib/ai/style-spec-projector.ts:315`, `ARCHETYPE_TO_TEMPLATE['caption-bar-bottom'] = 'magazine-bold'`
  at line 141). It does NOT touch the project-level `template_id`.
- `magazine-bold` has `backgroundMode: 'image-with-bottom-card'`
  (`src/lib/render/templates/magazine-bold.ts:43`) and `backgroundColor: '#000000'`
  (line 38) — so without a `caption_bar_color` override the bar would be BLACK.
  The screenshot's bar is pale YELLOW → the slide carries a `caption_bar_color`
  override and the canvas resolves+renders it correctly.
- `resolvePerSlideTemplate` (`src/lib/render/resolve-per-slide-template.ts:40-44`)
  reads `slide.template_id_override ?? slide.style_overrides?.template_id_override`.
  The card's gate passes ONLY when one of those slots resolves to a
  bottom-card template. The canvas renders the yellow bar because
  `slide-canvas`/`slide-preview` resolve the per-slide template the same way
  (quick-260515-epn). The gate failure mode the fix must close: any slide that
  visibly renders a bottom card but whose `CaptionBarControls` gate disagreed
  with the renderer — the card must follow the renderer, not the project template.

THE FIX
- The card's gate and the renderer's `useBottomCard` gate must use the IDENTICAL
  condition on the IDENTICAL resolved template. Both already test
  `backgroundMode === 'image-with-bottom-card'`; the card already receives the
  resolved template. The robust fix is a one-line guarantee in `elements-panel.tsx`
  + hardening the gate so the card is shown whenever the slide renders a bottom
  card. See Task 1.

WHAT NOT TO DO
- No new override field, no schema/migration change, no renderer change — the
  yellow panel already has a working override + resolver. Adding a field would
  duplicate `caption_bar_color`.
- Do not build a new color picker — `CaptionBarControls` already uses the
  `COLOR_SWATCHES` swatch-row + palette-icon pattern (quick-260515-nfb).
</investigation_findings>
