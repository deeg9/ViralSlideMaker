# Quick Task 260518-8o0: Unify news-layout black headline backdrop with the Caption card - Context

**Gathered:** 2026-05-18
**Status:** Ready for planning

<domain>
## Task Boundary

On news-layout slides, the solid black region behind the headline (e.g. "ORACLE
CUTS 30,000 JOBS IN MASSIVE SHAKEUP") is currently the slide root
`backgroundColor` showing below the top-constrained news photo. It is NOT the
Caption card — so the editor's "Caption card" toggle reads OFF even though a
black caption-like block is plainly visible. The user reported this mismatch.

**Goal:** Unify the two. The news-layout headline backdrop should BE a caption
card — driven by the existing `caption_bar_*` / `resolveCaptionBar` system —
so the toggle reflects reality and the caption-card controls (color, opacity,
snap, drag/resize) actually edit it.

</domain>

<decisions>
## Implementation Decisions

### Direction (locked — user picked "Unify them")
- The news-layout black headline backdrop is replaced by the caption-card
  system. The caption card becomes the single mechanism for "a colored block
  behind the caption" on ALL slides, including news-layout slides.

### Toggle OFF behavior (locked — user picked "Toggle OFF removes the block")
- The "Caption card" toggle stays a real toggle on news-layout slides.
- ON (default for news slides): the colored caption block renders behind the
  headline.
- OFF: the block is removed entirely — the headline sits directly over the
  photo / raw slide background. No forced-on, no disabled toggle.

### Geometry (locked — user picked "Freely draggable")
- On news-layout slides the caption card is a freely draggable/resizable
  rectangle, exactly like the caption card on regular slides — NOT locked to
  the bottom region.

### Default state for news-layout slides (Claude's discretion, derived from the above)
- News-layout slides should default to `caption_bar_enabled: true` with the
  caption-card geometry/color seeded so the slide looks IDENTICAL to today on
  first load (black block in the historical bottom region). This makes the
  toggle read ON out of the box, matching what the user sees.
- Because OFF must reveal the photo behind the headline, the news-layout photo
  must become a full-bleed background (it currently is constrained to the top
  `news_image_height%`). This aligns with the stated quick-260517-k2n design
  intent ("the photo is a permanent full-bleed background").

### Parity (non-negotiable)
- All three render paths must stay byte-parity: `slide-preview.tsx` (canvas
  preview), `render-slide-satori.tsx` (PNG export), `render-slide.ts` (HTML
  export). The shared `resolveCaptionBar` helper is the single source of truth.
- Phase 82 `resolveNewsHeadlineFit` is already caption-card-aware — preserve it.

</decisions>

<specifics>
## Specific Ideas / Investigation Findings

Key code references (verified during discussion):

- **The black region today:** `slide-preview.tsx` ~line 993-1016 `innerStyle`
  — `backgroundColor: overrides.background_color ?? template.backgroundColor`.
  In a news layout the photo is a constrained `<img>` (`newsBgImageNode`,
  ~line 1018) covering only the top `newsImageHeight%`; the area below shows
  this root background color.
- **News layout gate:** `slide-preview.tsx` ~line 838 `newsZone` (legacy
  `overrides.layout` + `NEWS_LAYOUT` presets) and `useBgMode` /
  `template.backgroundMode` (premium). `news_image_height` (quick-260517-iiy)
  moves the photo/caption boundary.
- **Caption card system:** `resolveCaptionBar()` in
  `src/lib/render/resolve-overlay.ts` ~line 502 — gated on
  `caption_bar_enabled === true`. Geometry/color fields:
  `caption_bar_{enabled,color,opacity,x,y,width,height_pct,position}`.
- **Caption card editor controls:** `src/components/editor/slide-background-controls.tsx`
  (toggle `caption-card-toggle`, color swatches, opacity slider, Top/Bottom
  snap). Mounted in the Elements tab via `ElementsPanel`.
- **Caption card render layer:** `slide-preview.tsx` ~line 221
  `CaptionCardLayer` / the editable `<Rnd>` for the caption card.
- **Recent churn to be aware of (all 2026-05-17):** quick-260517-k2n (caption
  card → draggable overlay), quick-260517-iiy (`news_image_height` control),
  quick-260517-h8z (`background_color` control "edit the bottom card
  background"), quick-260517-fu9/jfg. The h8z `background_color` control and
  the iiy `news_image_height` control may become redundant or need rewiring
  once the photo is full-bleed and the caption card owns the headline backdrop
  — the planner must decide explicitly (keep / rewire / retire) rather than
  leave a dead control.

### Migration of existing saved news slides
- Existing saved news-layout slides have NO `caption_bar_*` overrides. They
  must still render their black headline backdrop after this change — either
  via a load-time/migration seed of `caption_bar_enabled: true` + geometry, or
  via a resolver default that treats news-layout slides as caption-enabled
  when no explicit `caption_bar_enabled` key is present. The planner must pick
  one and keep it consistent across all 3 render paths.

</specifics>
