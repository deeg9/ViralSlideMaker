# Quick Task 260518-8o0: Unify news-layout black headline backdrop with the Caption card — Summary

The news-layout solid-black headline backdrop is now a real Caption card driven by the existing `resolveCaptionBar` / `caption_bar_*` system — one mechanism for "a colored block behind the caption" on every slide. `resolveCaptionBar` gained an `isNewsLayoutSlide` parameter that defaults an unedited news slide to an enabled bottom-region black card; the news photo is full-bleed in all 3 render paths; the editor "Caption card" toggle reads the resolved state (ON for unedited news slides) and writes an explicit `caption_bar_enabled: false` on OFF so the resolver default cannot silently re-enable it.

## What Changed

### Task 1 — News-layout default in `resolveCaptionBar`
- `resolveCaptionBar(overrides, template, isNewsLayoutSlide = false)` — new 3rd param, defaults `false` so every un-updated caller keeps today's behavior.
- New enabled gate: `o.caption_bar_enabled === true || (o.caption_bar_enabled == null && isNewsLayoutSlide)`. An ABSENT key triggers the news default; an EXPLICIT `caption_bar_enabled: false` does NOT (this is what lets "Toggle OFF removes the block" survive the default).
- The seeded geometry falls out of the EXISTING defaults — `heightPct = 38`, `position = 'bottom'`, `x = 0`, `width = 100`, `y = 62`, `backgroundColor = bottomCardBackground(template.backgroundColor)`. For a news template (`backgroundColor: '#000000'`) that is `rgba(0, 0, 0, 0.85)` — identical to today's backdrop. No extra seeding code.
- JSDoc updated to describe the news black-headline-backdrop migration.

### Task 2 — Full-bleed news photo + resolver wiring across all 3 render paths
- `render-slide.ts`: the news photo is folded into the full-bleed `background-image` branch of `backgroundCss` (the same path non-news photos use); `newsBgImageHtml` deleted; `isNewsLayoutSlide` hoisted and passed to `resolveCaptionBar`.
- `render-slide-satori.tsx`: the background `<img>` is full-bleed (`top: 0`, `width: W`, `height: H`) regardless of `newsZone`; `newsZone != null` passed to `resolveCaptionBar`.
- `slide-preview.tsx`: news photos now render full-bleed via `innerStyle.backgroundImage` (the `!newsZone` gate removed); `newsBgImageNode` deleted from both render branches; `isNewsLayoutSlide` threaded into `CaptionCardLayer` (new prop), the editable `<Rnd>` IIFE, and `captionBarForFit`.
- `news_image_height` resolver wiring retired in all 3 paths (it was dead once the photo is full-bleed — no movable photo/caption boundary; no editor UI ever wrote it).
- `background_color` KEPT — documented as the raw slide background, only visible when the caption card is OFF and there is no photo.
- `NEWS_LAYOUT` preset objects left intact — the `hookY`/`bodyY` text-position defaults are still used; only `imageTop`/`imageHeight` became unused.

### Task 3 — Editor toggle reads resolved caption state
- `captionPanelOn` now derives from `resolveCaptionBar(slide.style_overrides, template, isNewsLayoutSlide).enabled` — the panel calls the SAME resolver the 3 renderers use, so the toggle cannot drift from what renders.
- `isNewsLayoutSlide` computed locally in the component, mirroring the `render-slide.ts` gate (`template.backgroundMode == null && slide.style_overrides?.layout != null`).
- `setCaptionOff()` rewritten to write an EXPLICIT `caption_bar_enabled: false` (uniform — same code path for news and non-news slides) instead of deleting the key.
- File header doc + toggle JSX comment updated for news-layout awareness. The panel still NEVER emits `layout` / `news_image_height` / `background_color`.
