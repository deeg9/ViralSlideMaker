# Quick Task 260515-i3i: Fix Phase 81 UI HIGH findings

**Source of remediation:** `.planning/phases/81-first-run-onboarding-tour/81-UI-REVIEW.md` (EX-01 + EX-02)

## EX-01 — Welcome modal: backdrop/Esc destructive without warning

**Problem.** `handleOpenChange` in `src/components/onboarding/first-run-welcome-dialog.tsx` calls `handleSkip()` on every "open=false" event (X button, backdrop click, Esc). `handleSkip()` writes `onboarding_completed_at = now()`. A user accidentally pressing Esc on slide 2 silently disables the tour forever.

**Fix.** Split persistent-write from ephemeral-dismiss:
- Explicit text "Skip" button (the labeled affordance) → keeps `skipTour()` (DB write).
- X button / backdrop click / Esc key → call `markWelcomeSeen()` only. Modal closes for this session (welcomeSeen=true in localStorage), but `onboarding_completed_at` stays NULL — user gets the welcome modal next session.
- "Get Started" on slide 4 → unchanged (already calls `markWelcomeSeen()`).

This matches the convention in CR-01/CR-02 fixes (don't let accidental/ambiguous gestures write persistent state).

## EX-02 — Coachmark tooltip is keyboard-hostile and partly invisible to AT

**Problem.** In `src/components/onboarding/interactive-onboarding-checklist.tsx`:
1. Tooltip is NOT focus-trapped. A keyboard user tabbing while a spotlight is open will tab into the underlying page (`pointer-events: none` on the spotlight doesn't prevent focus traversal) and lose the tour controls.
2. Initial focus is not moved into the tooltip on mount. Screen-reader users will not hear the "Step N of 4 — {title}" announcement unless they manually tab to it.
3. `aria-label={step.title}` duplicates the visible `<h3>{step.title}`. Should be `aria-labelledby` pointing at the h3 to avoid duplicate AT announcement.

**Fix.** Three changes inside `CoachmarkOverlay` + `CenteredFallbackCoachmark`:
1. Wrap the tooltip body in Radix `<FocusScope trapped loop>` (already a transitive dep via `@radix-ui/react-dialog`). This gives focus trap + initial-focus-on-mount + focus restoration on unmount, for free.
2. Give the `<h3>{step.title}</h3>` inside `CoachmarkBody` a stable id (`coachmark-title-${step.id}`); switch the root tooltip/fallback `aria-label={step.title}` → `aria-labelledby={coachmark-title-${step.id}}`.
3. Add `tabIndex={-1}` to the FocusScope wrapper so it can receive initial focus.
