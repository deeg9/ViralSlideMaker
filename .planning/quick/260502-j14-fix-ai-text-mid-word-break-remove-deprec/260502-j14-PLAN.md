# 260502-j14 — Fix AI text mid-word break

## Symptom

AI-generated slide text wraps mid-word: `intellectu | al property,`, `creative owner | ship`, `newsle | tter.`. Words that would fit on the next line get broken at character boundaries instead of at word boundaries. The right-rail textarea wraps the same text correctly — only the slide canvas / Satori output is affected.

## Root cause

Three call sites set `wordBreak: 'break-word'` (a deprecated value) on segment + hook spans:
- `src/lib/render/resolve-overlay.ts:190` (highlighted segment span)
- `src/lib/render/resolve-overlay.ts:213` (plain segment span)
- `src/components/slides/slide-preview.tsx:436` (hook container)

Per MDN, `word-break: break-word` is a deprecated legacy alias that browsers now interpret as `word-break: normal` + `overflow-wrap: anywhere`. The `anywhere` behavior breaks at any character even when there's room on the next line — exactly the symptom. `overflow-wrap: break-word` (already set alongside) is the modern, less-aggressive rule that only breaks unbreakable strings.

## Fix

Remove the three `wordBreak: 'break-word'` lines. Keep the sibling `overflowWrap: 'break-word'` in place — it's the correct, modern wrap rule and is already set everywhere `wordBreak: break-word` was set.

## Verification

- `npx vitest run` — full suite green; no test currently asserts `wordBreak` so this is regression-net via the broader test pool.
- Live Playwright on the editor: pick a slide whose AI body text contains a long word at a line boundary (e.g., "newsletter" in slide 7 of project `e2389320…`). Confirm word now wraps cleanly instead of breaking mid-word.
- Visual check across all 6 templates' renders to be safe — but this property only affects wrapping, not visual layout, so rendering should be unchanged for short words.
