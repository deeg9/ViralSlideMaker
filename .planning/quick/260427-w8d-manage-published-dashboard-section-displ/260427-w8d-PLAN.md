# Quick Task 260427-w8d: Manage Published + display_name in welcome

## Context

Two polish gaps surfaced after v2.4 shipped:

1. **No UI to unpublish/delete published carousels.** The
   `unpublishCarousel` and `deletePublishedCarousel` server actions exist
   but no button anywhere calls them. Users who regret publishing have no
   recourse via the app.

2. **Dashboard "Welcome back, X!" reads from `user_metadata.first_name`**,
   ignoring the new `profile.display_name` shipped in 260427-nxd. First
   thing every dashboard user sees, ignores their actual name.

## Approach

One file changed (`src/app/(dashboard)/dashboard/page.tsx`) plus one new
component (`src/components/dashboard/published-list.tsx`). Both fixes ship
together — they live in the same screen.

### Fix #2: Welcome heading (1-line change)

Extend the `userName` fallback chain in `dashboard/page.tsx:13` to prefer
`profiles.display_name` over `user_metadata.first_name`. One SELECT query
on `public.profiles` (RLS allows it because the user is reading their own
row).

### Fix #1: Manage Published section

Add a "Published to Explore" section between the upgrade prompts and the
Recent Carousels list. Renders nothing if the user hasn't published
anything (no empty-state visual noise on a fresh account).

Each row:
- Hero thumbnail + title
- bookmark/remix counts
- "View" link → `/explore/[slug]`
- "Unpublish" button → soft-delete via `unpublishCarousel`
- "Delete" button → confirmed hard-delete via `deletePublishedCarousel`

Both buttons hit existing server actions; this task adds zero new
RPCs/migrations. Confirmation dialog uses `window.confirm` for v1 — no
custom modal needed for a destructive action this rare.

## Tasks

### Task 1: Welcome heading uses display_name

**File**: `src/app/(dashboard)/dashboard/page.tsx`

Add a profile fetch and update the userName fallback chain:
```ts
const { data: profile } = user
  ? await supabase.from('profiles').select('display_name').eq('id', user.id).maybeSingle()
  : { data: null }
const userName = (profile?.display_name as string | null)
  || (user?.user_metadata?.first_name as string)
  || user?.email?.split('@')[0]
  || 'User'
```

### Task 2: PublishedList client component + dashboard integration

**Files**:
- New: `src/components/dashboard/published-list.tsx`
- Edit: `src/app/(dashboard)/dashboard/page.tsx` — fetch user's published
  carousels and render the section

Server query (in dashboard/page.tsx):
```ts
const { data: published } = user
  ? await supabase
      .from('published_carousels')
      .select('id, slug, title, hero_image_url, bookmark_count, remix_count, unpublished_at')
      .eq('owner_id', user.id)
      .order('published_at', { ascending: false })
  : { data: [] }
```

The section renders only when `published.length > 0`. Each row shows the
fields above with three actions: View / Unpublish / Delete. Unpublish marks
`unpublished_at` so the row stays in the list with a "Hidden" badge but
isn't visible on /explore. Delete is permanent (with `confirm()`).

After Unpublish/Delete, `router.refresh()` re-fetches the list so the user
sees state update instantly.
