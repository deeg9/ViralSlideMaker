<picker_open_state_design>
<!-- isPickerOpenRef is a useRef<boolean>(false), NOT useState. Refs-only contract from v2.11
     (refs avoid re-render churn that React state would cause when picker open/close toggles).
     The setLucidePickerOpen / setShapePickerOpen state hooks DO use useState — they drive
     the JSX mount/unmount of the picker components. The REF mirrors the OR of those two
     boolean states — updated synchronously inside each picker's onOpenChange callback. -->

Pattern:
```tsx
const [lucidePickerOpen, _setLucidePickerOpen] = useState(false)
const [shapePickerOpen, _setShapePickerOpen] = useState(false)
const isPickerOpenRef = useRef<boolean>(false)

const setLucidePickerOpen = useCallback((open: boolean) => {
  _setLucidePickerOpen(open)
  isPickerOpenRef.current = open || shapePickerOpen
}, [shapePickerOpen])

const setShapePickerOpen = useCallback((open: boolean) => {
  _setShapePickerOpen(open)
  isPickerOpenRef.current = open || lucidePickerOpen
}, [lucidePickerOpen])
```

NB: keep the ref in sync with EITHER picker open state. A test (Test in SWEEP file) asserts
that opening LucidePicker, then opening ShapePicker, then closing LucidePicker → ref stays true
(because ShapePicker is still open).

Alternative simpler shape (Claude's discretion): a single setPicker({ kind: 'lucide' | 'shape' | null })
state — fewer race conditions. Recommend the alternative; document choice in code comment.
</picker_open_state_design>
