## Implementation Decisions

### Template authorship — file structure & registration

- **D-01: Each new template lives in its own file under `src/lib/render/templates/`** — `editorial-serif.ts`, `notes-app-chic.ts`, `brutalist-grid.ts`. Mirrors existing pattern (`magazine-bold.ts`, `tr3nding-news.ts`, `documentary.ts`). Each exports a single named `SlideTemplate` constant (e.g., `editorialSerif`, `notesAppChic`, `brutalistGrid`).

- **D-02: `templates` array in `index.ts` extended with 3 new entries** — appended at the end of the existing array so legacy templates retain their picker order (existing 8 templates unchanged → preserves picker UX continuity for current users).

- **D-03: All 3 new templates are FREE-tier (TPL-09)** — `PREMIUM_TEMPLATE_IDS` in `templates/premium-tier.ts` is NOT extended. Phase 55's `validatePremiumBodyFont` validator does NOT enforce `bodyFontFamily` on the new templates (they're not premium). However, all 3 new templates DO declare explicit `bodyFontFamily` voluntarily (per locked D-04) — anti-AI-slop discipline is universal, not premium-gated.

- **D-04: All 3 new templates declare explicit `bodyFontFamily` (free-tier benefit, not validator-enforced)** — research finding "no template defaults to Inter for body" is a universal v2.9 hygiene rule, not a premium gate. Locked body fonts:
  - `editorial-serif`: `bodyFontFamily: "'Spectral', serif"` — free Google Font; pairs with Playfair Display headlines per TYPO-02 catalog; Recoleta-equivalent at zero license cost
  - `notes-app-chic`: `bodyFontFamily: "'Plus Jakarta Sans', sans-serif"` — already in catalog; the ransom-note effect is on the HOOK only via segment-level overrides, body stays clean
  - `brutalist-grid`: `bodyFontFamily: "'Space Grotesk', sans-serif"` — added in Phase 55 catalog; sharp-modern sans pairs with the brutalist aesthetic

- **D-16: SVG asset authoring approach** — in-house SVG creation, NOT a licensed third-party set. Per Pitfalls research and Pre-PMF Discipline: zero IP risk, zero new dep cost. Each SVG is hand-authored as inline string in the planner-stage commit OR generated programmatically via `scripts/build-overlays.ts` (planner discretion).   - **Tape strips**: 240×60px viewBox, semi-transparent rectangle with subtle gradient texture, slight rotation; vary by color (peach/white/green) and roughness
  - **Sticky notes**: 240×240px viewBox, opaque rectangle with subtle shadow, slight rotation, color fill (yellow/pink/blue); empty interior — text would be a separate overlay layered on top in future enhancements
  - **Arrows**: 120×120px viewBox, hand-drawn-style stroke (slight wobble via `stroke-dasharray`-controlled path), single black stroke
  - **Polaroid frame**: 480×600px viewBox, white rounded-rect with thicker bottom border (the polaroid caption strip) and subtle drop shadow
  - **Paper torn-edge**: 1080×60px viewBox, jagged path simulating torn paper at top edge — used as decoration on photo edges

### Grain PNG asset set + build script (TPL-05)

- **D-17: `scripts/build-textures.ts` (NEW) generates all 5 grain PNGs deterministically via `sharp`.** `sharp` is already installed (Phase 54). Uses fixed seeded noise via `sharp.create({ ... })` + procedural compositions. Each PNG is 1080×1920, tileable, 8-bit grayscale-with-alpha. Strategy:
  - **Seeded noise**: use a fixed seed string per file. `sharp.create({ width: 1080, height: 1920, channels: 4, background: { r: 128, g: 128, b: 128, alpha: 0 } })` then composite Gaussian noise via `sharp.linear` + `sharp.modulate` chains with constant inputs. NO `Math.random()` — every randomized step uses a deterministic byte-source (e.g., a precomputed noise buffer from a fixed seed via `crypto.createHash('sha256').update(seed).digest()` expanded to fill the canvas).
  - **Output specs**:
    - `grain-subtle.png` — Gaussian noise σ=0.04, low-pass blurred radius=1
    - `grain-medium.png` — Gaussian noise σ=0.08, low-pass blurred radius=1
    - `grain-heavy.png` — Gaussian noise σ=0.14, ramped contrast +20%
    - `paper-texture.png` — base #F4EFE3 (paper-cream) + low-frequency noise (radius=12 blur) + occasional darker fiber streaks (5-10 hand-placed ellipses with seeded positions)
    - `xerox-grain.png` — high-contrast B&W noise (median filter for blocky photocopier feel, threshold around 0.5)
  - All 5 PNGs are tileable at 1080×1920 (canvas full-coverage; no edge-stitching required since canvas matches output).

- **D-18: Determinism contract** — `npm run textures` invoked twice produces byte-identical PNGs. Test: `scripts/build-textures.test.ts` runs the script, captures SHA-256 hashes of all 5 PNGs, runs again, asserts hashes match. CI does NOT run `npm run textures` (PNGs are committed to repo); it only runs the determinism test on a `git stash` + run + diff sanity check, OR snapshots the SHA-256s as a fixture.

- **D-19: `npm run textures` script in `package.json`:**
  ```json
  "textures": "tsx scripts/build-textures.ts"
  ```
  Mirrors existing `"thumbs": "tsx scripts/generate-template-thumbnails.ts"` pattern. Idempotent — overwrites existing PNGs.

- **D-20: PNG commit policy** — All 5 grain PNGs are committed to `public/textures/`. Phase 55 D-10 stipulated NO placeholder PNGs to be committed; Phase 56 commits the real generated PNGs in the same atomic plan as the script. No stub assets ever exist in main branch.
