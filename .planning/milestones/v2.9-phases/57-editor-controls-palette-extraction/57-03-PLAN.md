# Phase 57 Plan 03 — palette-dominant template flip + generation pipeline integration + retention audit

## Goal

Flip `editorial-serif` and `notes-app-chic` from `paletteMode: 'fixed'`
to `'palette-dominant'`. Wire the generation pipeline (`actions.ts`) to
call `extractPalette()` after `treatPhoto()` for palette-dominant
templates only. Both renderers consume the new resolver helpers so
identical JSX paths exist in Satori + React preview (TPLREND-05).
Audit Phase 54's pg_cron retention job and document the result.

## Requirements

- **PALETTE-02**: `slide.style_overrides.derived_palette` populated at
  generation time
- **PALETTE-03**: editorial-serif + notes-app-chic consume
  `derived_palette` (Vibrant for chip; DarkMuted for text on light)

### T5 — Generation pipeline integration

File: `src/app/(dashboard)/project/[id]/actions.ts`

Find the existing slide-creation flow where `treatPhoto()` is called
(Phase 56 D-27 wired this when `template.photoTreatment` is defined).
After the existing `treatPhoto` call, BEFORE persisting the slide:

```ts
import { extractPalette } from '@/lib/photo-treatment/palette'

// ... after treatPhoto() returns and slide.background_url is updated ...

// Phase 57 D-17/D-18: palette extraction on palette-dominant templates only
if (template.paletteMode === 'palette-dominant' && slide.background_url) {
  try {
    const named = await extractPalette(slide.background_url)
    slide.style_overrides = {
      ...(slide.style_overrides ?? {}),
      derived_palette: [
        named.Vibrant,
        named.DarkVibrant,
        named.LightVibrant,
        named.Muted,
        named.DarkMuted,
        named.LightMuted,
      ],
    }
  } catch (e) {
    console.warn('[generateCarousel] extractPalette failed:', (e as Error).message)
    // best-effort — slide creation continues without derived_palette
  }
}
```

Locate the EXACT integration point by inspecting actions.ts for the
existing treatPhoto call site (Phase 56 added it). The new block goes
immediately after.
