# Phase 86 — UI Design Contract

> Visual and interaction contract for the admin Save-as-Template page and the
> picker preview-PNG rendering. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker.

This phase has TWO user-facing surfaces:
1. **`(admin)/templates/save` page** — an admin-only authoring form (project
   selector, name input, category select, live cover preview, submit + states).
2. **Template picker tile** — renders a DB template's `preview` PNG when present,
   falling back to the existing live `<SlidePreview>` path.

The project already has a locked design system ("Bloom Rose Light" theme,
`src/app/globals.css`). This phase introduces NO new tokens, NO new component
library, NO shadcn init. Both surfaces reuse the existing primitives so the
admin page reads as a native settings-style page and the picker stays visually
unchanged for code templates.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/status-dot gaps |
| sm | 8px | Label-to-input gap (`mb-1.5` ≈ 6px is an accepted existing exception) |
| md | 16px | Form field vertical rhythm (`space-y-4`) |
| lg | 24px | Card padding, section padding |
| xl | 32px | Page header to form gap |
| 2xl | 48px | Major section breaks (form ↔ preview column gap on wide screens) |
| 3xl | 64px | Page-level top/bottom padding on the admin route |

Exceptions: `mb-1.5` (6px) label gap and `py-3` (12px) input height are
carried verbatim from the existing form idiom — kept for visual consistency
with `claim-username-form.tsx`. Picker tiles keep their existing `gap-4`,
`w-40`, `mb-3` values unchanged.

## Interaction & State Contract

**Admin page states:**
- **Loading** — server component; projects fetched before render. No skeleton needed.
- **No projects** — if the admin has zero carousels: render an empty state inside
  the form card — heading `No carousels yet`, body `Create a carousel first, then
  come back to save it as a template.` with a link to `/dashboard`. Submit hidden.
- **Idle** — all three fields empty/unset; submit `disabled` (opacity-40,
  not-allowed cursor) until project + non-empty name + category are all set.
- **Submitting** — submit shows `Saving…`, `disabled`; `active:scale-95`
  suppressed while disabled (existing pattern).
- **Success** — green confirmation block appears above the form; fields may
  reset; submit returns to idle. Accept the ≤60s registry-TTL delay (copy says
  "within a minute"). No redirect.
- **Error** — red error block with the reason; fields preserved; submit
  re-enabled.

**Picker tile (DB template with preview):**
- The `preview` PNG fills the 9:16 tile frame, `object-cover`, with the same
  `group-hover:scale-105` transition and selected/hover border as code tiles.
- Fallback: a DB template lacking a `preview` (or a code template) keeps the
  existing live `<SlidePreview>` render — zero visual regression (TPLREND-05).
- The tile must be visually faithful to the source carousel's cover (ADMIN-02):
  the PNG is the source cover snapshot, photo included.

**Accessibility:**
- Every input has a programmatic `<label htmlFor>` (existing idiom).
- The category `<select>` keyboard-operable natively.
- Submit `disabled` state communicated via the `disabled` attribute (not color
  alone).
- Preview PNG `<img>` carries descriptive `alt` text: `Preview of {template name}`.
- Focus ring `focus:ring-2 focus:ring-[#3d0000]/20` on all inputs (existing).
