Create src/lib/mcp/tools.ts exporting a `registerTools(server: McpServer)` function that registers all 4 tools.

The function receives the McpServer instance from createMcpHandler's setup callback. Use `server.tool(name, description, zodSchema, callback)` for each tool (the deprecated but stable API -- registerTool is newer but server.tool is what all mcp-handler examples use and is fully functional).

**IMPORTANT**: The tool callback receives `{ params, authInfo }` where `authInfo` comes from withMcpAuth. Access the userId via `authInfo?.extra?.userId as string`. The keyId is at `authInfo?.extra?.keyId as string`. If authInfo or userId is missing, return an MCP error content block.

**Tool 1: list_templates** (MCP-02)
- Description: "List available carousel visual styles/templates. Call this first to discover template IDs before creating a carousel. Returns id, name, textPosition, and textAlign for each template. No credit cost."
- No input parameters (pass empty zod object `z.object({})`)
- Implementation: Import `templates` from `@/lib/render/templates/index`. Return JSON content with `templates.map(t => ({ id: t.id, name: t.name, textPosition: t.textPosition, textAlign: t.textAlign }))`.
- Return format: `{ content: [{ type: 'text', text: JSON.stringify({ templates: [...] }) }] }`

**Tool 2: create_carousel** (MCP-01, INFRA-03)
- Description: "Create a new carousel from a topic. Generates AI content, fetches background images, and returns a project with download URLs. Costs 1 credit. Use list_templates first to pick a templateId, or omit for the default 'bold-minimal' style."
- Input schema (zod): `{ topic: z.string().min(1).max(500).describe('The topic or prompt for the carousel'), templateId: z.string().optional().default('bold-minimal').describe('Template ID from list_templates. Default: bold-minimal'), slideCount: z.number().int().min(3).max(20).optional().default(7).describe('Number of slides (3-20). Default: 7'), imageSource: z.enum(['stock', 'ai']).optional().default('stock').describe('Image source: "stock" for Pexels photos, "ai" for AI-generated. Default: stock') }`
- Implementation:
  1. Create admin Supabase client via `createAdminClient()`
  2. Check credit balance via `getCreditBalanceAdmin(supabase, userId)`. If < 1, return error content: `{ error: 'INSUFFICIENT_CREDITS', message: 'You need at least 1 credit to create a carousel', creditsRemaining: balance }`
  3. Deduct 1 credit via `deductCreditAdmin(supabase, userId, 'carousel_generation', 'MCP: ' + topic)`. If fails, return insufficient credits error.
  4. Call `generateCarousel(supabase, userId, { topic, templateId, slideCount, imageSource })`
  5. Build download URLs: for each slide index 0..slideCount-1, construct `/api/render?projectId=${projectId}&slide=${i}&download`. Build ZIP URL as `/api/v1/projects/${projectId}/download`.
  6. Return: `{ projectId, slideCount, downloadUrls: [...], zipUrl, creditsRemaining }` where creditsRemaining is fetched after deduction via getCreditBalanceAdmin.
- Wrap the entire implementation in try/catch. On error, return `{ isError: true, content: [{ type: 'text', text: JSON.stringify({ error: 'GENERATION_FAILED', message: error.message }) }] }`

**Tool 3: edit_slide** (MCP-03)
- Description: "Edit a slide in an existing carousel project. You can change the hook text, body text, search for a new background image, or set a direct image URL. Does not cost any credits. After editing, use render_carousel to get updated download URLs."
- Input schema (zod): `{ projectId: z.string().uuid().describe('Project ID from create_carousel'), slideIndex: z.number().int().min(0).describe('Zero-based slide index'), hookText: z.string().optional().describe('New hook/title text for the slide'), bodyText: z.string().optional().describe('New body/description text for the slide'), imageQuery: z.string().optional().describe('New search query for a Pexels background image'), backgroundUrl: z.string().url().optional().describe('Direct background image URL (must be https)') }`
- Implementation:
  1. Create admin Supabase client
  2. Fetch project via `getProject(supabase, userId, projectId)`. If throws, return not found error.
  3. Get slide_data array. Validate slideIndex is within bounds.
  4. Build patch object from provided optional fields (hookText -> hook_text, bodyText -> body_text, etc.)
  5. If at least one of hookText, bodyText, imageQuery, backgroundUrl must be provided -- return error if none given.
  6. If backgroundUrl is provided, validate it starts with 'https://'. Return error if not.
  7. If imageQuery is provided (and backgroundUrl is NOT), call `searchPhotos(imageQuery, { orientation: 'portrait', per_page: 1 })` and set the slide's background_url to the first result's `src.portrait`, and pexels_photo_id to `photos[0]?.id ?? null`. Also update the slide's image_query field.
  8. Apply field updates to the slide: `{ ...existingSlide, ...patchFields }`
  9. Write back via `updateProjectService(supabase, userId, projectId, { slide_data: updatedArray })`
  10. Return the updated slide object.

**Tool 4: render_carousel** (MCP-04)
- Description: "Get download URLs for all slides in a carousel project. Use this after create_carousel or edit_slide to get fresh image download links. No credit cost."
- Input schema (zod): `{ projectId: z.string().uuid().describe('Project ID from create_carousel') }`
- Implementation:
  1. Create admin Supabase client
  2. Fetch project via getProject. Return not found error if missing.
  3. Get slide_data. Return error if no slides.
  4. Build download URLs for each slide: `/api/render?projectId=${projectId}&slide=${i}&download`
  5. Build ZIP URL: `/api/v1/projects/${projectId}/download`
  6. Return: `{ projectId, slideCount, downloadUrls: [...], zipUrl }`

**General patterns for ALL tools:**
- Import `McpServer` type from `@modelcontextprotocol/sdk/server/mcp.js`
- Import `z` from `zod`
- Import `createAdminClient` from `@/lib/supabase/admin`
- All tool callbacks return `{ content: [{ type: 'text', text: JSON.stringify(result) }] }`
- Error returns use `{ isError: true, content: [{ type: 'text', text: JSON.stringify({ error: code, message: msg }) }] }`
- Download URLs are relative paths (no origin prefix) since the MCP client connects to the same host

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> tool handler | Untrusted tool parameters from AI agents cross into server-side service calls |
| tool handler -> Supabase | Authenticated DB access scoped to userId from auth token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Spoofing | tool authInfo | mitigate | All tools extract userId from authInfo.extra.userId (set by verifyToken after Bearer auth). Never accept userId as a tool parameter. |
| T-27-02 | Tampering | edit_slide backgroundUrl | mitigate | Validate backgroundUrl starts with https:// before storing. Reject http, data:, javascript: schemes. |
| T-27-03 | Information Disclosure | error messages | mitigate | Return generic error codes (NOT_FOUND, GENERATION_FAILED) without leaking internal stack traces or DB details. |
| T-27-04 | Denial of Service | create_carousel credit bypass | mitigate | Check credit balance AND call deductCreditAdmin (atomic RPC) before generating. Double-gate prevents race conditions. |
| T-27-05 | Elevation of Privilege | cross-user project access | mitigate | All getProject/updateProjectService calls include userId scope -- Supabase query filters by user_id. |
| T-27-06 | Tampering | slideIndex bounds | mitigate | Validate slideIndex >= 0 and < slide_data.length before array access. Zod schema enforces int().min(0). |
</threat_model>
