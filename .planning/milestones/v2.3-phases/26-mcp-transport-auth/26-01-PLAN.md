2. Create `src/lib/mcp/auth.ts` -- the verifyToken adapter for withMcpAuth.

   This function wraps the SAME auth logic as `authenticateApiKey` (from src/lib/api/auth.ts) but adapted for mcp-handler's interface. It does NOT import or call `authenticateApiKey` directly because that function takes a `NextRequest` parameter and throws errors, while `verifyToken` takes `(req: Request, bearerToken?: string)` and returns `AuthInfo | undefined`.

   Implementation (per INFRA-01 and INFRA-02):
   - Accept `(req: Request, bearerToken?: string)` signature
   - If `bearerToken` is falsy or does not start with `vsl_`, return `undefined`
   - SHA-256 hash the bearer token, look up in `api_keys` table via `createAdminClient()`
   - Timing-safe compare stored hash vs computed hash (same pattern as existing auth.ts)
   - Call `checkRateLimit(data.id)` -- if `!rl.success`, return `undefined` (rejects as auth failure; rate limiting is enforced per INFRA-02)
   - Fire-and-forget update `last_used_at` on the api_keys row
   - Return `AuthInfo` object: `{ token: bearerToken, clientId: data.id, scopes: [], extra: { userId: data.user_id, keyId: data.id } }`
   - The `extra.userId` and `extra.keyId` fields are critical -- Phase 27 tools will read these to scope data access and deduct credits

   Import `createHash, timingSafeEqual` from 'crypto', `createAdminClient` from '@/lib/supabase/admin', `checkRateLimit` from '@/lib/api/rate-limit', and the `AuthInfo` type from 'mcp-handler'.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-26-04 | Elevation of Privilege | middleware bypass | mitigate | /api/mcp bypass only skips Supabase session auth; Bearer token auth enforced by withMcpAuth with required: true |
