<objective>
Two wiring fixes that let a DB `template_id` survive into per-slide rendering
and into a fork — WIRE-04 and WIRE-05.

**WIRE-04 — per-slide override.** `resolvePerSlideTemplate` (the single source
of truth for per-slide `template_id_override` resolution) currently gates the
override through the code-only `TEMPLATE_IDS.includes(override)` allowlist —
so a per-slide override set to a DB template id is rejected and the slide
silently falls back to the project template.

The CONTEXT.md decision says "make `resolvePerSlideTemplate` async". A direct
asyncification is NOT viable: the helper is called inside the SYNCHRONOUS
builders `buildSlideElement` (render-slide-satori.tsx) and `buildSlideHtml`
(render-slide.ts), and by SEVEN `'use client'` components that resolve in their
render bodies (slide-canvas, sortable-slide, elements-panel, explore-card,
project-card, slide-grid, carousel-slideshow). Making it async would cascade
async into all of those plus ~40 parity test files. **This is a flagged
deviation from CONTEXT.md — see 88-CONTEXT.md "Per-Slide Override".** The
behavior CONTEXT.md asks for (a DB per-slide override resolves in the
consumable render) is delivered the non-breaking way:

`resolvePerSlideTemplate` stays SYNC and gains an optional 3rd parameter — a
`ReadonlyMap<string, SlideTemplate>` of DB templates. The async server render
routes pre-fetch that map once (new registry helper `getDbTemplatesMap()`) and
thread it through the builders into the helper. Client components pass nothing
(sync, code-only — byte-identical, zero blast radius). STYLESPEC-10 preserved:
unknown override → project template.

**WIRE-05 — fork inherits template_id.** The fork route
`src/app/api/v1/explore/[slug]/fork/route.ts` hardcodes
`template_id: 'highlight-bar'`. The `fork_published_carousel` Postgres RPC
ALREADY inherits the source template via `COALESCE(pub.template_id,
'bold-minimal')` (migration `20260512_v213_fork_inherits_template_id.sql`) —
so the bug is ONLY in the TS route, whose comment falsely claims it "mirrors"
the RPC. Fix the route to fetch + inherit `template_id`. No RPC change.
</objective>

export async function getDbTemplatesMap(): Promise<Map<string, SlideTemplate>> {
  const rows = await getDbRows()
  const map = new Map<string, SlideTemplate>()
  for (const r of rows) {
    if (CODE_TEMPLATE_ID_SET.has(r.id)) continue
    map.set(r.id, dbRowToSlideTemplate(r))
  }
  return map
}

  slide: Pick<Slide, 'template_id_override' | 'style_overrides'>,

  // callers omit it — they keep the code-only resolution, byte-identical to
