<objective>
Thread the `category` signal end-to-end — creation form → `generateCarousel` server action / v1 API → `generateSlideContent` → `buildSystemPrompt` — so the prompt module is selected by `category`, not `templateId`. Persist `category` on the project row. Insert the category selector into the creation form. Remove the silent `highlight-bar` fallback path.

Purpose: This is the integration plan that makes Phase 82's category framework live. After Plan 02 built the category registry and prompt modules, this plan wires them in: the user picks a category in the form, it threads through the whole generation chain, `buildSystemPrompt` switches on `category`, the project row records it, and every category always resolves to a curated template (no `highlight-bar` degradation).

Output: `buildSystemPrompt` switches on `category`; `generateSlideContent` + `generateCarousel` + the v1 API accept `category`; a `projects.category` migration + `Project` type field; a `CategorySelector` component inserted into `generation-form.tsx`; `autoPublishOnGenerate` confirmed still firing; a category-routing test.
</objective>
