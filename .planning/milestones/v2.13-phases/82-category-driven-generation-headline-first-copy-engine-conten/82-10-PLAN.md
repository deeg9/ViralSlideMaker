<objective>
Fix **Gap F** from the R10 round-3 visual sign-off: the same News headline wraps
DIFFERENTLY between the editor's read-only left thumbnail strip and the editable
main centre canvas. Both render the headline at the same font (112px Anton) with
the same words, but place line breaks at different points — confirmed via live
DOM: "APPROVES" + "MASSIVE" land on one line in the thumbnail and on two lines in
the canvas.

GAP F ROOT CAUSE (verified by reading the code):

`SlidePreview` has two headline render branches that must produce the same
canonical 1080x1920 layout (just scaled):

- **Read-only branch** (`!editable`, `slide-preview.tsx` ~line 1238): the headline
  is a plain `<div>` with `width: ${hookWidth}%` directly containing the text
  block. The text's flex-wrap container width === `hookWidth%` of the canvas.

- **Editable branch** (`editable`, `slide-preview.tsx` ~line 1778): the headline
  is rendered inside a draggable/resizable `<Rnd>` whose `size.width` is
  `hookWidthPx = (hookWidth / 100) * REF_WIDTH`. INSIDE the `<Rnd>` there is an
  inner wrapper `<div data-testid="hook-text-wrapper">` with `width: '100%'` AND
  `padding: '4px 8px'`. The text block sits inside that wrapper. The wrapper's
  `4px 8px` padding (8px left + 8px right = **16px**) subtracts from the
  headline's flex-wrap container width. So the editable headline's effective
  text width is `hookWidthPx - 16px`, while the read-only headline's is the full
  `hookWidth%` (= `hookWidthPx` at REF scale).

That 16px delta is enough to flip a flex-wrap break point: at the full box width
"APPROVES MASSIVE" fits on one line; 16px narrower it does not, so the canvas
splits them. Same font + same words + different container width → different wrap.

The Satori export (`render-slide-satori.tsx` ~line 309 `hookStyle`) renders the
hook as a single `<div>` at `width: hookTextWidth = pxX(hookWidth)` with NO
padding — it agrees with the read-only branch. So the EDITABLE branch is the lone
outlier; unifying it makes all three paths agree.

WHY THE 16px IS NEW-LOOKING: the inner-wrapper `4px 8px` padding predates the k2n
caption-card rework (it has been on the headline `<Rnd>` since Phase 13). The
divergence only became *visible* now because the Phase 82 R10 News-headline
auto-fit (`fitHeadlineToBox`, Plans 08-09) sizes the headline to fill its box
tightly — so a 16px width difference now flips a wrap point that slack used to
absorb. The fix is still in Gap F scope: unify the headline text-box width.

FIX (scoped, surgical — does NOT touch the caption-card `<Rnd>`):

The editable headline's inner wrapper `hook-text-wrapper` keeps its `4px 8px`
padding for the grab affordance / selection-ring inset, BUT the headline's
flex-wrap container must be given the SAME usable text width as the other two
paths. The clean fix: widen the editable headline `<Rnd>` by the wrapper's
horizontal padding (16px) and offset its x-position by half that (8px) so the
text content area lands at exactly `hookWidthPx` — the read-only / Satori width —
while the box still drags/resizes correctly and the wrapper padding stays.

Concretely, in `slide-preview.tsx` the editable headline `<Rnd>`:
- `HOOK_WRAPPER_PAD_X` constant = 8 (the horizontal padding, in px, applied each
  side by `hook-text-wrapper`'s `padding: '4px 8px'`).
- The `<Rnd>` `size.width` becomes `hookWidthPx + 2 * HOOK_WRAPPER_PAD_X` so the
  inner wrapper's content box (after subtracting `2 * HOOK_WRAPPER_PAD_X`) is
  exactly `hookWidthPx` — identical flex-wrap container width to the read-only
  div and the Satori `pxX(hookWidth)` box.
- The `<Rnd>` `position.x` is shifted left by `HOOK_WRAPPER_PAD_X` so the
  *text* still starts at the same canvas x as the read-only branch (the box
  visually grows symmetrically around the text, not off to one side).
- All drag/resize commit math that converts the `<Rnd>` pixel geometry back to
  persisted `hook_position` / `hook_width` percentages MUST subtract the same
  `2 * HOOK_WRAPPER_PAD_X` / add back `HOOK_WRAPPER_PAD_X` so a drag or resize
  still commits the SAME `hook_position.x` / `hook_width` the read-only branch
  consumes — i.e. the padding compensation is invisible to persisted state.

This makes the editable canvas, the read-only thumbnail, and the Satori PNG all
give the headline a flex-wrap container of exactly `hookWidth%` of the canvas, so
they wrap identically.

NON-GOALS / GUARDRAILS:
- Do NOT touch the caption-card `<Rnd>` (`ccWpx` / `ccHpx` / `onCaptionBarUpdate`)
  — the k2n draggable/resizable caption card is out of scope and must keep
  working.
- Do NOT change the read-only branch or the Satori export — they are already the
  canonical width; the editable branch is the one outlier being brought in line.
- Do NOT regenerate every render-parity snapshot. The Satori export and the
  read-only DOM are unchanged by this fix; only the editable-branch DOM changes.
  If any committed snapshot covers the editable branch and changes, regenerate
  ONLY that one and state it explicitly.
- Verify against the HEAD render-parity baseline (5 pre-existing failures from
  the earlier `quick-260515-o75` hook-casing drift: `news-drop` byte-identical +
  `highlight-bar`/`news-drop`/`y2k-pop`/`bold-yellow` legacy-regression). Do not
  attribute those to this work or "fix" them.
