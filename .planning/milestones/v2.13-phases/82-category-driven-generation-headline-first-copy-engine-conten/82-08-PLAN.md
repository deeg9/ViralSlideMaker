<objective>
Fix **Gap D** from the R10 round-2 visual sign-off: the generated news headline overflows the slide and breaks mid-word.

ROOT CAUSE (verified in `src/lib/ai/categories/promote-news-headline.ts:29,152-154`):
`promoteNewsHeadline` sets `style_overrides.hook_font_size` to a FLAT
`NEWS_HEADLINE_FONT_SIZE = 200` on EVERY news slide regardless of how long the
headline is. A short headline at 200px is fine; a long one ("MAJOR TECH COMPANY
ANNOUNCES 19,000 LAYOFFS") at 200px is far too big — it overflows the hook box
and forces mid-word wrapping ("ANNOUNCE" + orphaned "S" — ref
`~/Desktop/Screenshot 2026-05-17 at 3.04.57 PM.png`).

The user's explicit ask: "font size logic relative to where the text is and where
the caption card / black box is." Target: `~/Desktop/Screenshot 2026-05-17 at
3.06.22 PM.png` — the headline (~142px there) is cleanly contained in the bottom
black caption card, whole words.

FIX (this plan): replace the flat constant with a content-aware **auto-fit**.

1. **`hook-fit.ts` — new `fitHeadlineToBox(headline, box)` function.** Given a
   headline string and a target box `{ widthPx, heightPx }`, compute the largest
   integer font size (within a sane ceiling/floor) such that:
   - the LONGEST single word fits within `widthPx` at that size (so no word ever
     needs to break — this also removes Gap E's mid-word-break at the sizing
     layer), AND
   - the headline, wrapped whole-word into `widthPx`, produces a line count whose
     total height (`lineCount * fontSize * LINE_HEIGHT`) fits within `heightPx`.
   Use the same condensed-font char-width model the existing `HOOK_FIT_REGISTRY`
   comments cite (Anton ≈ `0.45 * fontSize` average advance per char — see
   `hook-fit.ts:21-26`). The function is PURE — no DOM, no measurement API — so it
   runs identically server-side (Satori), client-side (canvas preview), and at
   generation time.

2. **`promote-news-headline.ts` — size via `fitHeadlineToBox`, drop the flat 200.**
   `promoteNewsHeadline` currently writes `hook_font_size: 200`. Instead it computes
   the size by calling `fitHeadlineToBox(hook_text, NEWS_DEFAULT_HEADLINE_BOX)`
   where `NEWS_DEFAULT_HEADLINE_BOX` is the news hook-zone geometry on the
   1080x1920 canvas (the news templates' hook box — `hook_width` ~78% of canvas
   ≈ 842px wide; the cover-layout hook zone height — see below). The flat
   `NEWS_HEADLINE_FONT_SIZE` export is REMOVED.

3. **Caption-card awareness (the k2n integration).** `260517-k2n` reworked the
   caption card into a draggable/resizable rectangle (`resolveCaptionBar` in
   `resolve-overlay.ts` — `x`/`y`/`width`/`heightPct` percents, opt-in via
   `caption_bar_enabled`). The auto-fit MUST work WITH it: when a news slide has
   a caption card enabled, the headline must fit the CAPTION CARD box, not the
   default hook zone. `promoteNewsHeadline` runs at GENERATION time — generated
   news slides do not enable a caption card by default, so generation fits to the
   default news hook box. The RENDER paths (Plan 09 wires the renderer side; this
   plan exposes the function and the box-from-caption-card helper) compute the
   caption-card box from `resolveCaptionBar` when one is enabled. This plan
   delivers the pure sizing primitive + a `captionCardBox(resolved)` helper that
   converts a `ResolvedCaptionBar` (minus its padding) into a `{ widthPx, heightPx }`
   box on the 1080x1920 canvas, so Plan 09's renderer wiring has a ready primitive.

DO NOT break the k2n caption-card rework: `fitHeadlineToBox` and `captionCardBox`
are ADDITIVE pure functions in `hook-fit.ts`; `resolveCaptionBar` is read-only
consumed, never modified.

    1) Export a `HeadlineBox` interface: `{ widthPx: number; heightPx: number }`.

    2) Export constants:
       ```
       export const HEADLINE_FIT_CEILING = 240
       export const HEADLINE_FIT_FLOOR = 64
       const HEADLINE_LINE_HEIGHT = 1.1   // mirrors hookStyle.lineHeight in both renderers
       const CONDENSED_CHAR_ADVANCE = 0.50 // avg glyph advance as a fraction of font size, Anton-ish; slightly conservative vs the registry's 0.45 so the fit never overflows
       ```

    3) Export `fitHeadlineToBox(headline: string, box: HeadlineBox): number`:
       - Trim the headline. If empty, return `HEADLINE_FIT_FLOOR`.
       - Split into whole words on `/\s+/`.
       - For a candidate font size `S`, define:
         * `charWidth(S) = S * CONDENSED_CHAR_ADVANCE`
         * `longestWordPx(S) = max over words of (word.length * charWidth(S))`
         * whole-word wrap: greedily pack words into lines where each line's
           summed word widths + inter-word spaces (`charWidth(S)` per gap) is
           `<= box.widthPx`; count the resulting lines. A word longer than
           `box.widthPx` on its own still occupies its own line (it would
           overflow — the longest-word constraint below rejects that `S`).
         * `totalHeightPx(S) = lineCount(S) * S * HEADLINE_LINE_HEIGHT`
       - A size `S` FITS iff `longestWordPx(S) <= box.widthPx` AND
         `totalHeightPx(S) <= box.heightPx`.
       - Search for the LARGEST integer `S` in `[HEADLINE_FIT_FLOOR, HEADLINE_FIT_CEILING]`
         that fits. Iterate downward from the ceiling (or binary-search) and return
         the first fitting `S`. If even `HEADLINE_FIT_FLOOR` does not fit (a
         pathologically long single word), return `HEADLINE_FIT_FLOOR` anyway —
         the floor is the hard minimum; whole-word wrapping in Plan 09 keeps it
         readable. Always return an integer (`Math.round` / `Math.floor`).
       - Pure function — no DOM, no try/catch needed, never throws on string input.

    4) Export `captionCardBox(resolved: ResolvedCaptionBar, inset?: number): HeadlineBox`:
       - Import `CANVAS` and the `ResolvedCaptionBar` type from `./resolve-overlay`.
       - Convert the resolved percents to pixels on the 1080x1920 canvas:
         `widthPx = (resolved.width / 100) * CANVAS.W`,
         `heightPx = (resolved.heightPct / 100) * CANVAS.H`.
       - Subtract `2 * inset` from each dimension (default `inset = 80` — the
         old bottom-card padding, so the headline does not touch the card edges).
       - Clamp both dimensions to a minimum of 1 so a tiny card never yields a
         negative box. Return `{ widthPx, heightPx }`.

    Add a file-level comment block above the new exports citing Phase 82 Gap D:

    is the pure sizing primitive, `captionCardBox` derives the box from a k2n
