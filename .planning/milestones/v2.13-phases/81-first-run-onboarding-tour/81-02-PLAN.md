       ```typescript
       interface OnboardingContextValue {
         needsOnboarding: boolean       // server-seeded; profile.onboarding_completed_at IS NULL
         welcomeSeen: boolean           // localStorage-backed (onboarding_welcome_seen_at)
         activeStepId: OnboardingStepId | null
         completedStepIds: readonly OnboardingStepId[]
         isComplete: boolean            // completedStepIds covers all ONBOARDING_STEPS
         steps: readonly OnboardingStepDef[]
         markWelcomeSeen: () => void
         startStep: (id: OnboardingStepId) => void
         completeStep: (id: OnboardingStepId) => void
         dismissActiveStep: () => void
         skipTour: () => void           // user clicked Skip (welcome or checklist) — fires server action
         finishTour: () => void         // user completed all 4 steps — fires server action
         resetTourState: () => void     // used by settings restart redirect into /dashboard
       }
       ```

       `skipTour` and `finishTour` need to invoke the server action `markOnboardingComplete` (Plan 06). For now (Plan 02), accept an optional prop `onComplete?: () => void | Promise<void>` on the provider that both methods call. Plan 05 wires the real action.

    3. The Provider:
       ```typescript
       export interface OnboardingProviderProps {
         needsOnboarding: boolean       // from server component
         onComplete?: () => void | Promise<void>  // server action invoker, wired by Plan 05
         children: React.ReactNode
       }
       export function OnboardingProvider({ needsOnboarding, onComplete, children }: OnboardingProviderProps) { ... }
       ```

       Initial state:
       - `needsOnboarding` from props.
       - `welcomeSeen` = false initially (server render); hydrate from `localStorage.getItem('onboarding_welcome_seen_at')` in a `useEffect` after mount.
       - `activeStepId` = null.
       - `completedStepIds` = [] (resets on reload — D-17 v1 behavior).

       Methods:
       - `markWelcomeSeen()` sets local state + writes `localStorage.setItem('onboarding_welcome_seen_at', new Date().toISOString())`.
       - `startStep(id)` sets `activeStepId = id`. (Plan 04 calls this when checklist row clicked.)
       - `completeStep(id)` pushes to completedStepIds (de-duped) and clears activeStepId. If completedStepIds now covers all 4 step IDs, schedule `finishTour()` on next tick (so consumers see isComplete=true once before the tour unmounts).
       - `dismissActiveStep()` clears activeStepId without marking complete.
       - `skipTour()` and `finishTour()`: both call `onComplete?.()`. Optimistically set `needsOnboarding = false` so the welcome modal hides immediately (server action revalidates on next nav).
       - `resetTourState()` clears `localStorage.removeItem('onboarding_welcome_seen_at')`, resets all in-memory state, and sets `needsOnboarding = true`. Settings restart triggers this AFTER the server nulls the column.

       Wrap localStorage access in `try / catch` and guard with `typeof window !== 'undefined'` for SSR safety.

       Compute `isComplete` via `useMemo` from `completedStepIds.length === ONBOARDING_STEPS.length` AND every ONBOARDING_STEPS id appears in completedStepIds.

       ```typescript
       export function useOnboarding(): OnboardingContextValue {

       }
       ```
