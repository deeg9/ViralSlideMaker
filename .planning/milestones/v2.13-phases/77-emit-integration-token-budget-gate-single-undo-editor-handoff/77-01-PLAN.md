<objective>
Stand the three pure helpers Phase 77's emit pipeline depends on:

1. **applyAspectFilter** — Phase 76 wired `state.aspects: { palette, typography, layout, decorations }` checkboxes; this helper consumes a StyleSpec + aspects flags and returns a copy with unchecked sections replaced by neutral defaults. Keeps the projector pure (it consumes spec only — never reads aspect flags directly).

2. **applyBrandKitRemix** — Phase 76 wired `state.useBrandKitRemix: boolean`; when true, this helper overrides spec.palette + spec.typography per-field with brand-kit values (brand kit wins for overridable fields). Pure; null brand-kit short-circuits to identity.

3. **projectStyleSpecToSlideOverrides** — the LOAD-BEARING projector for EMIT-07. Translates StyleSpec sections (palette / typography / layout / imagery / decorations) into the existing `SlideStyleOverrides` shape. Zero new Slide fields introduced — by type construction, not by promise. Decorations.preferredLucide / preferredShapes return a NARROWED allowlist that Plan 02 will pass into the Gemini responseSchema's `enum:` array, so the AI emit can only pick decorations the spec endorses.

All three modules are pure functions with zero I/O — no React, no Gemini SDK, no Supabase. This makes them 100% unit-testable in isolation, and lets Plan 02 mock them trivially for the orchestrator + roundtrip tests.

Purpose: Deterministic, byte-identical, side-effect-free transformations. The projector is the seam where StyleSpec semantic fields become Slide concrete fields — getting it right (and pure) is what protects TPLREND-05 byte-identity and unblocks the EMIT-09 roundtrip test in Plan 02.

Output: 3 source modules + 1 type module + 3 test files. No reducer changes, no Server Action changes, no UI changes.
</objective>
