<!-- Z-order semantics (Figma model, per ARCHITECTURE.md and CONTEXT.md):

For "bring forward" (op = 'forward') on a multi-selection within an array:
  - Sort selected indices DESCENDING.
  - For each index i in that order: if i < array.length - 1, swap array[i] with array[i+1].
  - Sorting DESC ensures higher-indexed elements move first — moving the topmost
    of two adjacent selected elements first prevents the lower one from being
    moved into its just-vacated slot.

For "send backward" (op = 'backward'):
  - Sort selected indices ASCENDING.
  - For each index i: if i > 0, swap array[i] with array[i-1].

For "bring to front" (op = 'front'):
  - Sort selected indices DESCENDING.
  - For each index i (in DESC order): splice element out at i; push to end of array.
  - DESC sort ensures the order among the selected group is preserved
    (highest-indexed selected ends up topmost).

For "send to back" (op = 'back'):
  - Sort selected indices ASCENDING.
  - For each index i (in ASC order): splice out at i; unshift to position 0.
  - ASC sort ensures the lowest-indexed selected ends up bottommost.
-->

    Cleaner implementation strategy — operate on a snapshot of `[id, originalIdx]` tuples sorted by sort discipline, then build the next array by simulating swaps/moves:

    ```typescript
    export function applyZOrderToArray<T extends { id: string }>(
      arr: T[],
      selectedIds: Set<string>,
      op: ZOrderOp,
    ): T[] {
      if (arr.length === 0 || selectedIds.size === 0) return arr
      const next = arr.slice()
      const desc = op === 'forward' || op === 'front'

      // Helper: find the current index of an id in `next` (since prior
      // iterations may have moved it).
      const idxOf = (id: string): number => next.findIndex(el => el.id === id)

      // Build an iteration order over original ids — sort by ORIGINAL index
      // (DESC for forward/front, ASC for backward/back).
      const iterIds: string[] = arr
        .map((el, i) => ({ id: el.id, i }))
        .filter(({ id }) => selectedIds.has(id))
        .sort((a, b) => desc ? b.i - a.i : a.i - b.i)
        .map(({ id }) => id)

      let changed = false
      for (const id of iterIds) {
        const i = idxOf(id)
        if (i === -1) continue
        if (op === 'forward') {
          if (i < next.length - 1 && !selectedIds.has(next[i + 1].id)) {
            // Don't swap with another selected element — would clobber its move.
            // But because we iterate DESC, the i+1 element may already have
            // been moved. The real Figma semantics: each selected moves +1
            // ONLY if its new neighbor is unselected.
            ;[next[i], next[i + 1]] = [next[i + 1], next[i]]
            changed = true
          }
        } else if (op === 'backward') {
          if (i > 0 && !selectedIds.has(next[i - 1].id)) {
            ;[next[i], next[i - 1]] = [next[i - 1], next[i]]
            changed = true
          }
        } else if (op === 'front') {
          if (i < next.length - 1) {
            const [el] = next.splice(i, 1)
            next.push(el)
            changed = true
          }
        } else if (op === 'back') {
          if (i > 0) {
            const [el] = next.splice(i, 1)
            next.unshift(el)
            changed = true
          }
        }
      }

      return changed ? next : arr
    }
    ```

    The `!selectedIds.has(next[i+1].id)` guard implements PITFALL-6.3 / ZA4 / ZA8 / ZA15 (adjacent selected window doesn't shift). For 'front' and 'back' the move is unconditional within bounds because the splice shifts the entire selected group to the end / start in DESC / ASC order — preserving relative order among selected.
