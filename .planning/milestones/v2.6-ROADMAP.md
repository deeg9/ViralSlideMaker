Rebuild the retired v2.3 MCP server end-to-end with a lean 4-tool scope. Ship a working `/api/mcp` Streamable HTTP endpoint that lets Claude Desktop, Cursor, ChatGPT, Windsurf, and other MCP-aware AI agents call ViralSlideMaker tools natively — closing the failure mode that retired v2.3 (`mcp-handler` was in `package.json` but missing from `node_modules` → `/api/mcp` returned HTTP 500).

## Key Decisions

- **Lean 4-tool scope locked early.** Broader v2.5 REST surface (publish, fork, bookmarks, brand-kit, profile, credits, AI image gen, Pexels search) deferred to v2.7+ to ship faster and validate the MCP path before expanding.
- **Build-gate regression as the headline feature.** v2.3's failure mode was a missing dep silently making the route return 500. v2.6 closes this with three independent layers: (1) static non-type import in route.ts triggers Next.js module resolution at build time, (2) vitest import-gate test asserts symbols exist, (3) `npm run build` in CI exercises both. Triple coverage so this exact failure cannot recur.
- **Tools call services directly, never re-enter `/api/v1/*` HTTP routes.** Avoids double auth, double rate limit, double credit deduction. Enforced by grep audit in Phase 41 plan.
- **Auth core extraction.** `src/lib/api/auth-core.ts` exports `verifyApiKeyHash(rawKey)` shared between REST `withApiAuth` and MCP `verifyToken`. Eliminates `NextRequest` coupling in the MCP path.
- **Insufficient credits is in-band, not OAuthError.** OAuth errors are auth-layer only in mcp-handler. Tool-level errors (credits, validation, NOT_FOUND) return `{ isError: true, content: [...] }`.
- **Zod raw shape for tool inputs.** `inputSchema: { topic: z.string() }` — wrapping with `z.object({...})` silently breaks input validation per mcp-handler API.
- **`templateId` REQUIRED in create_carousel.** No default — `bold-minimal` was removed in v2.5. Agent must call `list_templates` first.
- **`edit_slide` does NOT auto-fetch Pexels.** Match REST exactly. Setting `image_query` updates metadata only.
- **Stateless transport for Vercel.** `sessionIdGenerator: undefined`, `disableSse: true`, `redisUrl: undefined`.
- **AuthInfo cross-phase contract.** `verifyToken` returns `{ extra: { userId, keyId } }` so Phase 41 tools can read auth context via `extra.authInfo?.extra?.userId`.
