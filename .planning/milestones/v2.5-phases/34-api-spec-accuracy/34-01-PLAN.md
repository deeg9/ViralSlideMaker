# Phase 34, Plan 01 — Bring openapi.ts in line with current types

## Why

`/docs` (Scalar API reference, served from `src/app/docs/[[...slug]]/route.ts`)
renders `src/lib/api/openapi.ts`. The spec was written before several
data-model expansions — TextSegment two-color spans, TextEffects
(shadow / outline / highlight), `layout` cover/body, per-slide
`hide_watermark`, project `description` / `generation_status`. Customers
reading the reference can't see fields the API actually accepts, and
client codegen (e.g. `openapi-typescript`) loses type safety for those
fields.

This plan is **spec-only**. No route handlers change, no behavior
changes. Lowest-risk wedge of the v2.5 milestone.

## What ships

In `src/lib/api/openapi.ts`:

1. New schemas:
   - `TextSegment` — `{ text, accent? }`
   - `TextShadowEffect` — `{ enabled, color, size: 'sm'|'md'|'lg' }`
   - `TextOutlineEffect` — `{ enabled, color, width: 1-8 }`
   - `TextHighlightEffect` — `{ enabled, color, style: 'tight'|'full', padding: 4-24 }`
   - `TextEffects` — composite `{ shadow?, outline?, highlight? }`
2. `StyleOverrides` gains: `hook_text_effects`, `body_text_effects`,
   `layout` ('cover'|'body'), `hide_watermark`.
3. `CustomText` gains: `text_effects`, `segments`.
4. `Slide` gains: `hook_segments`, `body_segments` (both `TextSegment[]`).
5. `Project` gains: `description`, `generation_status` (enum: draft /
   generating / complete / error).
6. `/carousel` POST `200` response body schema upgraded with `required`
   array and per-field descriptions. Shape unchanged; just
   tightened.

## Verification

- `npx tsc --noEmit | grep openapi` returns nothing.
- `grep -c "TextSegment:\|TextEffects:\|hook_segments:\|hide_watermark:\|generation_status:"` in openapi.ts returns the expected hits.
- `curl -sL -o /dev/null -w "%{http_code}\n" http://localhost:3000/docs` → 200.
- Manual check: load `/docs` in browser, expand `Slide` and `Project` schemas, confirm the new fields are listed.

## Out of scope

No behavior change. The `PATCH /slides/{index}` handler still rejects
custom_texts/custom_images/segments — expanding the handler is API-02
in Phase 35.
