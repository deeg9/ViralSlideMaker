## Cross-Phase Integration — verified (inline; no Agent subagent available in this runtime)

All cross-phase wiring confirmed present in the codebase on `main`:

1. **83 → 86 (registry):** `src/app/api/admin/templates/route.ts` imports `resolveTemplate` from the Phase 83 merged registry and `TEMPLATE_IDS` from `index.ts` — the save flow checks the merged registry for id collisions.
2. **84 → 86 (extraction):** the admin route imports and calls `extractLayoutRecipe` (Phase 84) → writes `layout_recipe` + `flat_style` columns on the new `templates` row.
3. **86 → 86 (preview):** the admin route imports `renderCoverPreviewPng` and uploads to the `template-previews` bucket; `dbRowToSlideTemplate` carries `row.preview` onto `SlideTemplate.preview`; `TemplateTilePreview` renders it.
4. **84 → 85 (generation):** `applyLayoutRecipe` / `resolveLayoutRecipe` are wired into both generation paths — `src/lib/services/carousel.ts` and `src/app/(dashboard)/project/[id]/actions.ts` — plus the recipe semantic-hint block in `src/lib/ai/prompts.ts`.
5. **Admin gate (86):** `(admin)/layout.tsx` calls the shared `requireAdmin` and `redirect('/dashboard')`s non-admins server-side; `POST /api/admin/templates` re-checks `requireAdmin` → 403. Single source of truth (`src/lib/auth/admin.ts`).

E2E flows traced: (a) admin saves carousel → template row + preview → appears in picker; (b) user generates on a recipe-carrying template → pre-shaped output via `applyLayoutRecipe`; (c) non-admin blocked at both page and endpoint. All three are exercised by phase tests.
