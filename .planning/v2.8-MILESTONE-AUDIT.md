# v2.8 Text Editor Right-Rail Redesign — Milestone Audit

## Original intent

> Replace the cluttered, dual-slot ("Hook" + "Body") text editing panel with a selection-driven, single-element right rail that supports an arbitrary number of text boxes per slide and stacks Shadow / Outline / Highlight as independent toggleable effects. Pattern grounded in 2026 industry research (Figma, Canva post-Glow Up, CapCut, VEED, Adobe Express).

User pain points (from `/gsd-new-milestone` invocation, 2026-04-30):
1. ✅ "We shouldn't have probably a hook text and a body text. We should just name it text box one, text box two..." — addressed by selection-driven panel + LayerStrip
2. ✅ "...have all the styling under that text box for whatever text box that person's adding" — addressed by ActiveTextBoxCard
3. ✅ "Shouldn't we just highlight words? Why is it all spaced out like that?" — addressed by AccentWordsDisclosure (collapsed by default with count badge)
4. ✅ "Shadow outlining, highlight, they should all just be accordion dropdowns" — addressed by EffectRow toggle-with-inline-reveal pattern (research found this beats true accordions per NN/g for design tools)
5. ✅ "Make the text box or the text editing darker than the rest of the page" — addressed by `bg-white border-2 border-[#3d0000]/20` framing on cream `#fff0f0` panel
6. ✅ "Find out what people do successfully and let's copy them" — Figma/Canva/CapCut/VEED patterns sourced via WebSearch + WebFetch during planning

## Cross-phase integration check

**End-to-end data path verified:**
1. AI generation (Phase 51) → slides arrive with both `text_boxes[]` and legacy fields populated
2. Save to Supabase → both shapes persisted (Phase 49 dual-write)
3. User opens project → eager migration on load is no-op (text_boxes already populated)
4. User edits in new panel (Phase 50) → reducer `applyDualWrite` keeps both shapes in sync
5. Live preview reads legacy → reflects edits instantly (Phase 50 BL-01 fix)
6. Save → both shapes persist
7. PNG export reads legacy → byte-identical output to v2.7 for unchanged content (Phase 53 reasoning)
8. Canvas selection (Phase 52) → click hook/body/custom on canvas → right rail mirrors instantly

**Reducer write-through pattern (Phase 50 `applyDualWrite`)** is the keystone integration. It eliminated the need for MIG-01 (mandatory backfill) and MIG-02 (read-path feature flag) by guaranteeing both shapes are always in sync after any edit.
